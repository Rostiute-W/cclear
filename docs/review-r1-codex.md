# CClear 第 1 轮独立评审（Codex）

评审日期：2026-11-13。对象：`docs/plan-v1.md`、`docs/scan.md`。

**立场：支持“分析 + 分级清理 + 官方迁移优先”的产品方向；建议选 B 的 WPF 路线，版本改为 .NET 10 LTS。当前方案可以进入只读原型阶段，但永久删除、提权执行和自动迁移前，必须解决下文 P0 项。**

本轮仅阅读材料、列举部分本地目录名称、查询卷与开发环境信息、查阅官方文档；没有运行清理、维护、迁移、安装、停服务或提权操作，没有读取聊天、文档、凭据内容。只新增本评审文件，不修改两份输入文档。本轮是设计评审，不涉及代码实现、Git 初始化或代码提交。

## 一、证据与判断边界

1. `scan.md` 是非管理员扫描，其目录体积可用于确定调查顺序，不能直接当成可删除量。部分不可读、硬链接重复、压缩文件、稀疏文件、云占位文件都会影响统计。“纯垃圾 1–2 GB”只能标为初步估计，尚未经过逐文件规则筛选与可回收空间验证。
2. 本轮查询时 C 盘剩余约 33.6 GiB，D 盘约 90.7 GiB，G 盘约 99.7 GiB；C/D/E/F/G 均报告为固定 NTFS 卷。数值会随其他进程变化。D 盘可以作为候选目标，但不能硬编码为唯一隔离盘，也没有验证其备份策略、磁盘健康或长期可用性。
3. 本机可找到 `dotnet`、`rustup`、`cargo`、`node`、`npm`、`uv`。只读列举标准 .NET SDK 目录发现 `9.0.315`，没有发现 .NET 10 SDK；这不是完整的跨安装位置盘点，也没有执行构建。已装 rustup 同样不能证明 Tauri 的 Windows 构建依赖齐全。
4. 实际目录结构已确认：
   - `%APPDATA%\Kingsoft` 下有 `personalofflinecache`、`WPS Cloud Files`；`office6` 下同时有 `backup`、`cache`、`log`、`wpsdrive` 等。
   - `%APPDATA%\QQ`、`%APPDATA%\QQEX` 下存在 `Cache`、`Code Cache`、`GPUCache`，同时存在账户、配置和网页存储目录。
   - `%APPDATA%\Tencent\xwechat` 下有 `login`、`config`、`log`、`update` 等；`%APPDATA%\DingTalk` 下有 `Temp`、`image_res_cache`、`globalStorage`、`wukong` 等。
   - `%USERPROFILE%\.cache` 下存在 `huggingface`、`paddle`、`babeldoc`、`pdf2zh`、`pdf2zh_next`、`puppeteer`、`codex-runtimes` 等。
   - `%LOCALAPPDATA%\qianfan-desktop-app-updater` 下存在 `installer.exe`。
5. 上述检查只证明路径存在，未证明某个目录全部可删除，未核验应用版本、文件用途、占用状态、完整大小或清理后的可恢复性。下文将这些内容明确列为候选、人工项或待验证条件。

## 二、逐条回答原方案第 7 节

### 1. 技术栈选 A/B/C 中哪一个？

**选 B：C# + .NET 10 LTS + WPF，不选 WinUI 3 作为首版框架。**

这个工具只服务 Windows 上的一个用户，复杂度主要来自 Windows 文件语义、权限、Shell 回收站、重解析点、应用占用和恢复流程。WPF 足够承载列表、目录树、进度、确认页；使用一个 C# 技术栈，更容易贯通 UI 与 Windows API。需要的 Win32/COM 调用仍要认真封装和验证，WPF 本身不保证文件操作安全。

- 将方案中的“.NET 8”更新为“.NET 10 LTS”：按本轮日期，.NET 8 已于 2026-11-10 结束支持。[S1] 当前机器缺少已确认的 .NET 10 SDK，正式实现前补齐并验证；本轮不安装。
- 首版采用普通 WPF 桌面应用、按需短生命周期 helper；不引入服务、常驻托盘、MSIX 或复杂插件框架。扫描/计划/执行保持独立于 UI 的职责边界即可，不必先搭通用规则平台。
- A 是可接受的第二选择：如果实际承担实现的人明显更熟悉 React/Rust，可选 Tauri 2，但需要证明这能降低总维护成本。Tauri 还需要 C++ Build Tools、WebView2，且必须限制 IPC 命令及其参数；仅“已装 rustup”不足以决定选型。[S2]
- 原稿“Rust 扫描快”“Python 扫描慢”没有本机对照实验。枚举性能往往受文件数量、磁盘访问、元数据查询、杀软和并行度影响，不能仅按语言下结论。“Python 容易误杀进程”也不是成立的技术栈属性；若指打包产物被杀软误报，应另行描述和验证。
- 不选 C 的主要理由是该项目需要较多 Windows 文件/权限交互，PySide6 打包和多层调用会增加维护面；并非 Python 天然不能高效扫描。

### 2. 提权模型选按需 helper 还是整个程序管理员运行？

**选普通权限主程序 + 按需 UAC helper，反对整个 GUI 默认管理员运行。**

用户缓存、空间分析和普通文件迁移无需扩大权限。系统目录不可读时，展示“扫描不完整”，提供单独的管理员补充扫描；不要自动重启整个 GUI 为管理员。

原稿 `--elevated-task <plan.json>` 只能是传输入口，不能把 plan 文件当可信执行脚本：

1. helper 只识别内置任务 ID、受限参数和已确认的项目集合；不接受任意命令行、任意路径或用户 TOML 提供的管理员操作。
2. helper 独立检查路径、卷、文件身份、规则版本和操作类型；不能相信客户端传来的 `risk=safe`、`admin=true` 或“已检查”标记。
3. 绑定启动请求、调用者身份与本次任务；限制计划文件和日志 ACL，避免解析期间被替换，使用受控 IPC 或安全读取后的不可变任务数据。计划哈希只能辅助检查，不能替代身份验证和权限隔离。
4. 提权时重新确认系统目录；用户目录按原始调用者 SID 对应的 Known Folder 解析。若 UAC 使用另一个管理员账户，不可把 helper 的 `%LOCALAPPDATA%` 当原用户目录。
5. helper 跑完即退出；取消 UAC 不影响普通权限结果。Windows 系统程序使用受信任的绝对路径；第三方开发工具原则上只以普通权限运行。

同一 exe 的无界面 helper 模式可以实现，不必为了“隔离”多建服务；关键是权限边界与输入验证。

### 3. caution 默认永久删除还是默认隔离？

**对支持文件级恢复的 caution 项，默认隔离到用户选择的其他本地卷；不默认永久删除。对官方维护命令，单列“不可撤销操作”并逐项确认，不能假装有隔离能力。**

- 用户仍须主动勾选 caution 项。目标卷缺失、空间不足、无法保留必要元数据或无法保证数据一致性时，停止该项，不自动退回永久删除。
- 跨卷“移动”实际上是复制、验证、删除源文件，必须沿用迁移的事务与恢复机制；禁止直接把普通跨卷 Move 当成原子操作。首版可先完成极少量已验证缓存的显式永久删除，把隔离功能放到可靠迁移基础完成后上线。
- 隔离区应使用独立任务目录和原始相对路径清单，不覆盖已有文件。目标 ACL 至少不得扩大原数据的可读范围；无法做到时不隔离敏感数据。
- 将“保留 N 天后自动清掉”改为“到期后在下一次手动打开时提示清空并确认”。不创建后台任务；不让一次隔离授权在用户不知情时转化为永久删除授权。
- 回收站是用户数据的撤销缓冲，必须从 safe 列表移除。清空时限定 C 卷和当前用户，显示选中内容及不可恢复提示；不要一个入口清空所有盘的回收站。
- 送回收站失败或目标不支持回收站时不得静默改成永久删除。C 卷文件进入 C 卷回收站不会释放该卷空间，这一点原稿正确。

### 4. 微信/QQ/钉钉/WPS 缓存里哪些子目录可以确定安全？

**基于目前证据，没有一个可跨版本、跨用户数据布局直接认定为 safe 的通用路径清单。首版这些应用不进入一键安全清理；优先调用或引导应用内存储管理。**

可以建立以下“精确路径候选清单”，但只能作为 caution 规则验证对象。不能按 `*cache*`、`*temp*` 名字递归匹配整个用户目录。

| 应用 | 本机候选及判定 | 必须保护的范围/具体落地建议 |
|---|---|---|
| QQ / QQEX | `%APPDATA%\QQ\Cache`、`Code Cache`、`GPUCache`，以及 `%APPDATA%\QQEX` 下同名目录已存在。仅这几个精确叶目录可优先验证 Chromium 缓存规则 | 先核验所属应用与版本，用户退出应用及辅助进程，再做沙箱/备份恢复验证。保护 `auth`、`security`、`users`、`mega-db`、`Network`、`Local Storage`、`Session Storage`、`IndexedDB`、配置文件等；不要顺带清理未核验的 `Partitions`、`blob_storage` 或小程序数据 |
| 微信 | 当前看到的是 `%APPDATA%\Tencent\xwechat`；没有足以确认通用安全缓存叶目录的证据 | 先识别实际版本和应用设置中的数据位置；禁止整删 `Tencent`、`WeChat Files`、`xwechat_files`、`Tencent Files`，以及聊天库、附件、文件接收、备份和登录数据。`log`/`crashinfo` 最多是经保留期筛选的诊断信息清理候选，仍需确认 |
| 钉钉 | `%APPDATA%\DingTalk\Temp`、`image_res_cache`、`image_translate_cache` 名称像缓存，但本轮未验证语义 | 首版引导应用内清理；保护账号子目录、`wukong`、`globalStorage`、离线文档、待上传内容、下载与同步文件。不能因名为 `Temp` 就永久删除 |

### 5. Windows Installer 孤立补丁（8.5 GB）要不要做？

**不做自动删除、不做隔离、不做 junction 迁移；v1 只展示体积和官方说明。**

必须先纠正题设：扫描得到的是 `C:\Windows\Installer` 总计约 8.5 GB，材料没有证明其中存在任何孤立补丁，更不能将 8.5 GB 标为可回收空间。

Microsoft 明确说明该缓存用于修复、更新和卸载，删除后的故障可能延后出现。[S3] 仅凭文件老旧、应用列表里没有对应项、注册表未搜索到文件名等都不足以确定安全；安装上下文、多用户/每机器注册、补丁依赖和未完成的维护操作会使简单关联检测失效。

若未来单独研究，应先做完整只读安装关系报告、标记“未关联”而非“孤立可删”，在虚拟机快照及完整恢复条件下验证相关产品的修复、升级、卸载。即使如此，也不应纳入当前通用清理器承诺。“先移到 D 盘以后再放回来”不能保证期间 MSI 维护成功。

同理，`%ProgramData%\Package Cache` 和 `%LOCALAPPDATA%\Package Cache` 不能因名字为 Cache 就认作残留；当前只展示、引导产品官方卸载/修复。

### 6. junction 迁移有哪些坑？

**保留为高级人工操作，放到官方配置迁移之后；只支持已明确允许的普通用户目录，首版拒绝系统、安装、同步与特殊文件树。**

主要风险及修改步骤：

1. **目标与权限：** junction 可指向其他本地卷，不适用于网络映射目标。[S4] 本产品先限定固定 NTFS 卷。`mklink /J` 通常不要求符号链接特权，但创建位置 ACL、受保护目录等仍可能导致失败；不能承诺所有位置免管理员。目标应是全新空目录，不覆盖、不合并，且不能是源的祖先/后代或同一实体。
2. **运行状态：** 退出主窗口不等于没有写入者。辅助进程、更新器、服务、杀软和同步工具都可能继续访问。用占用检测辅助提示；无法保证静止时中止。不能强杀应用，也不能在用户不知情时停服务。复制期间和切换前检测源清单变化。
3. **校验：** 文件数和总字节一致不能发现同大小损坏或遗漏替换。数据迁移至少按相对路径核对逐文件内容哈希、数量与长度，并验证复制前后源没有变化；保留必要的时间戳、ACL、备用数据流等。对 EFS、云占位、重解析点、无法保真的 ADS、稀疏/压缩特性、跨树硬链接，首版拒绝或单独提供经过验证的专用方案。不要把读取云文件、触发下载叫作无副作用检查。
4. **事务：** 建议顺序为“预检与记录 → 复制到任务临时目录 → 完整校验 → 再确认无变化/无写入者 → 源同卷改名为唯一备份名 → 目标定名 → 创建 junction → 验证最终目标及应用功能 → 用户确认提交”。每个不可逆步骤前后持久化 journal，崩溃重启先恢复未完成任务，不开启新清理。
5. **不要立即删除 `.bak`：** 切换后先保留原副本以便切换失败恢复，明确这时 C 盘尚未释放空间；完成应用实测后再让用户确认清除备份。源备份也可能被旧打开句柄继续写入，因此不能仅靠改名隔离写入。
6. **区分两种回滚：** 尚未接受新写入的切换失败可恢复原目录；迁移后已使用过的目标包含新数据，不能简单删 junction 再把旧 `.bak` 改回。此时需停止写入，把目标最新数据复制回 C、校验、解决冲突并切换，且 C 盘必须有足够空间。不要承诺无条件“一键回滚”。
7. **应用生态：** 更新器可能拒绝 junction、删除链接或重建原目录；UWP/MSIX 的 `%LOCALAPPDATA%\Packages`、WindowsApps 不走通用迁移；OneDrive/其他同步根、Known Folders、离线云文件使用对应官方迁移入口；杀软可能阻止切换，不能建议关闭保护或接管目录所有权。
8. **后续清理：** 全盘扫描默认不跟随该 junction，显示“已迁移至目标卷”；迁移管理可按已记录目标单独检查。清理链接时只能操作链接本身，禁止递归进入目标。D 盘不可用时展示故障，不自动创建新的 C 盘目录掩盖问题。

官方配置迁移也需要“记录旧配置 → 选择目标 → 停止相关写入 → 迁移/重建 → 修改配置 → 用新进程验证实际生效路径 → 确认旧目录不再使用 → 单独确认清理旧副本”。环境变量只影响之后启动的进程，不保证已有 IDE/终端立即切换。

### 7. 还漏掉哪些高价值清理项或风险？

**高价值应由本机已有体积与可恢复性共同决定，优先分析下面这些目录，先不扩张系统清理规则。表中大小都引用原扫描，不是新增测量或预计收益。**

| 方向 | 原扫描体积/线索 | 建议操作与限制 |
|---|---|---|
| HiBit 备份 | Roaming 下约 5.2 GB | 先展开实际备份/恢复点目录，辨别用途、时间、保留需求，通过 HiBit 自身管理或人工迁移；不能直接算安装残留 |
| AI/科研缓存 | `.cache` 约 4.9 GB，已发现模型、翻译和浏览器运行时目录 | 拆分模型权重、下载缓存、运行时、输出/本地修改，优先官方缓存位置配置。模型可能体积大且离线必需；不整删 `.cache` |
| uv 缓存 | 约 1.7 GB | 使用其官方缓存命令，优先评估 `uv cache prune`，需要清空时另行确认 `uv cache clean`；取消直接删目录兜底。迁移前同时考虑环境所在卷和硬链接收益。[S5] |
| 开发工具与运行时 | `.rustup` 约 2.7 GB、`.vscode` 扩展约 2.9 GB | 列出已安装与项目所需版本，用户通过官方卸载操作移除不用的工具链/扩展；不用“旧文件夹”推断未使用 |
| 应用安装与更新包 | updater 约 0.73 GB；`Local\Programs` 约 4.1 GB | updater 文件先核对安装/更新状态和用途，确认后作为单独候选；Programs 是应用安装目录，不是缓存，应进入官方卸载建议 |
| agent 数据 | `.codex` 约 3.7 GB、`.dsh` 约 0.70 GB、`.workbuddy-ai` 约 1.3 GB | 只能按实际目录职责继续分析；会话、配置、凭据、技能和项目状态都可能在其中。未明确识别的内容保护，不整删或自动迁移 |

## 三、按优先级排序的修改清单

P0 表示必须在相关破坏性能力开放前解决；P1 表示首个实用版本应具备；P2 可后置。优先级按数据/系统风险排序，不表示本机已发生故障。

### P0：破坏性执行前的准入条件

| 编号 | 原方案位置与问题 | 具体修改建议/验收标准 |
|---|---|---|
| P0-01 | §3.2/3.3 将回收站、WER、CrashDumps 等整体标为可再生 safe | 回收站改为独立 caution；诊断报告/转储并非可再生内容，需按保留期和用户确认处理。通用 Temp 的“24 小时 + 未锁定”不能证明可删：未打开的文件仍可能被应用或安装器再次使用。首版通用用户/Windows Temp 归 caution；仅经验证的具体缓存子规则可进入 safe，必要时 safe 列表为空 |
| P0-02 | §3.1 官方命令缺失时退回直接删目录 | 删除默认 fallback。工具缺失、版本不支持、锁等待超时或命令失败，结果为“跳过并说明原因”；不得扩大删除范围。uv 尤其明确禁止直接修改缓存。[S5] 官方命令也必须绑定实际配置目录及运行上下文，不能先扫描默认 C 路径，却执行命令清空了配置在其他卷的缓存 |
| P0-03 | §3.5 helper 信任外部 plan/规则 | 仅固定操作 ID、受限参数、可信绝对可执行路径；独立验证调用者、计划身份和文件对象；管理员操作不加载任意用户命令。测试替换 plan、修改参数、PATH 劫持和 UAC 更换账户，确保不能越权 |
| P0-04 | §6 路径护栏只有“根目录内 + 不跨 reparse” | 不用字符串前缀判归属（`C:\Cache2` 不属于 `C:\Cache`）。验证完整路径组件、最终卷/文件 ID、所有祖先重解析点，拒绝设备路径、未经支持的命名空间与 ADS 目标；文件和目录链接都不能跟随。扫描到执行间可能被替换，操作时必须重新验证，并采用可证明不会在检查后跟随替换链接的句柄/父目录约束；仅执行前再次 canonicalize 仍有竞态。测试不得删除 allowlist 外的哨兵文件 |
| P0-05 | §3.3/3.4 隔离与迁移没有完整数据一致性协议 | 采用第二节第 6 项的预检、内容校验、分步日志与恢复流程。无法保真、源变更、空间不足、链接创建失败均保留原数据；不立即清除 `.bak`；迁移后的回滚必须保留目标的新数据 |
| P0-06 | §3.2 私有系统存储与 MSI 范围不够明确 | Installer、Package Cache、WinSxS 文件、DriverStore、WindowsApps、Program Files/Program Files (x86)、系统保留文件禁止通用删除/迁移。Windows Temp 等确需支持的操作必须作为独立窄范围规则例外，不能为其放开整个 Windows 根。SoftwareDistribution 手工删 Download 先移到“官方系统清理引导”，不把单停 wuauserv 当充分条件 |
| P0-07 | §3.3 dry-run 只显示样例，执行对象与预览可能不一致 | 文件级任务冻结明确清单，记录规则版本、对象身份、大小/时间与排除项；执行仅处理该清单，新增/变更文件跳过并要求重扫。允许展开完整列表。官方命令无法给出逐文件 dry-run 时，显示其作用范围与估算限制，不承诺“只删预览文件”。取消后只停止后续动作，明确已完成的删除不可撤销 |

针对 P0-04 再补两条：不得为删除失败而自动接管所有权、重置 ACL 或改硬链接文件属性；“手动大文件”入口也必须受同样的系统目录保护，不能绕过规则层。用户自定义规则只能增加候选，不能解除硬性禁止范围。

### P1：首版实用性与可信结果

| 编号 | 问题 | 具体建议 |
|---|---|---|
| P1-01 | 目录体积、计划删除量、真正释放空间混用 | 分别展示逻辑大小、已分配大小（不可读则未知）、预计可回收量、执行后的卷可用空间变化。按卷 ID + 文件 ID 去重硬链接；删除部分链接不一定释放数据块，不能把去重后的体积直接当回收量。规则重叠、父子目录选择合并去重；并行遍历的共享去重必须一致。卷空闲差值受其他进程影响，只称“观测变化” |
| P1-02 | 默认全盘并行扫描和“只读零风险”表述过强 | 先扫已知候选与用户目录，再按需全盘；限制并行度，持续进度与取消，报告拒绝访问/重解析点/变化项。云占位文件只取元数据，不读内容、不跟随挂载点，不提权遍历其他用户。只读表示不主动修改，不等于无 I/O 负载或零副作用 |
| P1-03 | 原计划先完成复杂清理，M4 才有空间分析 | 把目录列表和 Top N 前移到 M1，先支撑最有价值的大目录判断；treemap 后置。候选大小未知或语义未验证时不可选中执行 |
| P1-04 | 应用生命周期与命令执行语义欠缺 | 默认要求用户自行正常退出；占用无法解除则跳过，不强杀 Explorer/浏览器/开发进程。命令按受控参数数组运行并识别退出码、部分失败、重启需求；不拼接任意 shell。长任务有日志/进度，不把命令已启动当作完成，不因 UI 关闭强杀系统维护进程 |
| P1-05 | 隔离与历史缺少持久化约束 | 每项记录计划、实际动作、结果、错误原因、源/目标标识和恢复状态；日志失败时不要继续新的破坏步骤。使用追加记录/原子更新与必要落盘，启动检查未完成操作。日志不记文件内容或命令中的秘密值；可导出时提示路径可能包含个人信息。隔离过期清空必须另行确认 |
| P1-06 | 迁移工具配置存在性能/正确性影响 | 为 uv/npm/pip 等分别解析真实缓存位置和配置优先级。跨卷迁移 uv 缓存可能失去与环境的硬链接并增加复制成本。[S5] 不把 CARGO_HOME/RUSTUP_HOME 当缓存开关；整体迁移要处理可执行文件、配置、凭据、PATH 和工具链关联，首版仅给专用指引 |
| P1-07 | 规则驱动删除面过大 | v1 使用少量内置、固定操作的规则，TOML 仅作内部描述或暂不引入。自定义任意命令/提权脚本后置。每条规则需有默认勾选状态、实际根目录解析、排除条件、证据、恢复级别和可适配版本；“safe/caution”只是标签，不能直接决定执行权限 |

### P2：后续增强

1. 基于实际扫描瓶颈再决定并行策略、增量索引或 USN/MFT 优化；不为首版引入驱动、常驻索引器或“极速扫描”复杂机制。
2. treemap、趋势图、更多应用适配和主题后置；优先保证列表解释清楚、路径可打开、计划可核对。
3. 通用 junction 迁移、复杂隔离保真、Docker/WSL 空间回收向导、用户规则编辑器分开验收，不捆绑进首次清理上线。
4. 根据实际使用再考虑日志保留策略与安装包形式；开发构建输出/依赖缓存可优先放 G 盘，避免工具开发本身继续挤占 C 盘，但不能未经确认自动迁移现有开发环境。

## 四、建议修订后的里程碑与验收

| 阶段 | 范围 | 最低验收条件 |
|---|---|---|
| M0 | 确认 WPF/.NET 10 或有证据改选 Tauri；普通权限骨架 | 可启动、可退出；无服务、托盘常驻、计划任务；构建和依赖位置可控 |
| M1 | 只读扫描、Top N、规则候选、空间口径 | Unicode/长路径/拒绝访问/硬链接/重解析点/稀疏与云占位等处理可解释；无递归环；取消可用；跳过范围和未知大小可见 |
| M2 | 计划、路径护栏、日志、最小 safe 执行 | 先在临时测试树中证明不会越界；执行仅处理预览集合；锁定、变化、失败均报告；未验证的 Temp/应用目录不能进入 safe。一键按钮基于已展示的合格安全集合，不混入 caution |
| M3 | 少量开发工具官方操作、按需 helper | 每项清晰告知不可撤销性与作用范围；命令缺失/失败不兜底删目录；UAC 拒绝和计划篡改不会导致执行 |
| M4 | 官方配置迁移、可靠复制与恢复、必要的隔离 | 内容和元数据校验通过；目标不覆盖；中断后源或已验证副本可恢复；过期隔离不会静默删除 |
| M5 | 有限 allowlist 的 junction 迁移及迁回 | 备份未释放空间提示准确；应用验证后再确认清备份；使用后的迁回保留最新数据；空间不足拒绝，失败状态可恢复 |

原稿已有的 Unicode、长路径、只读、占用、junction 测试值得保留，但“穷举测试”应改成可检查的风险矩阵。至少再覆盖：

- **越界与对象变化：** 同前缀兄弟目录、`..`、文件/目录重解析点、祖先在预览后被替换、硬链接指向规则外数据、文件在执行前被同名替换；规则外哨兵内容与元数据不变。
- **选择与体积：** 重叠规则、父子同时选中、多个链接只删其中之一、压缩/稀疏文件、拒绝访问不记作零字节；显示不能虚增回收量。
- **操作失败：** 磁盘写满、ACL 拒绝、占用、应用重开、源在复制中变化、哈希不一致、目标目录已存在、日志写失败、UAC 取消、命令超时/部分失败；不扩大范围或升级权限兜底。
- **恢复：** 在复制中、源改名后、junction 创建前后、备份清除前分别模拟进程退出/重启；随后新写入与迁回也需测试。重复恢复不得重复删除或覆盖唯一有效副本。
- **Shell 与系统维护：** 送回收站取消/不支持时不得永久删除；DO/组件维护仅在可还原测试环境验证。此类操作通常没有完整逐文件 dry-run，不能拿预览通过代替真实隔离环境测试。

本轮没有执行这些测试，不能据此宣称删除或迁移实现已安全。评审建议的准入标准是：先使最小操作范围可验证，再逐条增加规则；无需等待通用系统清理平台建成才交付只读分析价值。

- **[S4]** Microsoft [Hard Links and Junctions](https://learn.microsoft.com/en-us/windows/win32/fileio/hard-links-and-junctions)。用于本地跨卷 junction 与同卷硬链接边界；不构成应用支持迁移的保证。

- **[S7]** Microsoft [Monitor Delivery Optimization](https://learn.microsoft.com/en-us/windows/deployment/do/waas-delivery-optimization-monitor) 与 [Delete-DeliveryOptimizationCache](https://learn.microsoft.com/en-us/powershell/module/deliveryoptimization/delete-deliveryoptimizationcache?view=windowsserver2025-ps)。命令参考部分说明仍为占位内容，不能据此自行推导所有边界；首版优先系统入口，命令支持性与行为需匹配本机 Windows 验证。
