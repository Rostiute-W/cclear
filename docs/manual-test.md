# CClear 手工验收清单

这份清单用于在真机上逐项验收 T03–T17 的功能。自动化测试覆盖的是护栏、执行器、隔离和迁移这些会造成数据损失的逻辑；界面、占用检测、提权、系统维护只能手工验证。

## 验收原则

1. **先只读，再动手**。每次打开应用先走一遍扫描、分析、预览，确认数字正常，再做执行类操作。
2. **先预览**。所有清理都必须经过“清理预览”确认，看清单和体积对得上再点执行。预览里看到的东西就是实际会处理的东西。
3. **每步之前记录 C 盘剩余空间**。只有这样才能判断“实际回收”与“预计回收”是否一致；不一致就记下来，别跳过。
4. **普通权限运行**。不要用“以管理员身份运行”启动主程序；需要管理员的操作会自己弹一次授权提示。
5. **别拿重要数据试**。真实清理会真的删掉缓存，第一次验收建议在能承受重装缓存的环境里做。

### 每步之前记录 C 盘剩余空间

在 PowerShell 里执行，把数字抄到下面这张表里，或者自己另开一张：

```powershell
Get-PSDrive C | Select-Object @{n='FreeGB';e={[math]::Round($_.Free/1GB,2)}}
```

## 1. 扫描与总览（T03）

1. 记录 C 盘剩余空间，启动应用。
2. 看总览页：C 盘环形图显示已用/剩余，下面列出其他固定盘。
3. 点“扫描”区的 C 盘按钮，观察进度。

预期：
- 扫描中显示目录数、文件数、已统计大小和耗时，可以点“取消扫描”。
- 扫描结束后显示摘要，路径是 `C:\`；如果有拒绝访问的目录，出现“N 个目录无权读取（普通权限扫描不完整）”。
- 顶部徽标显示“普通权限”和版本号。
- 扫描全程 C 盘剩余空间不变（只读）。

4. 再扫描“用户目录”，重复一次；扫描到一半点“取消扫描”。

预期：
- 取消后摘要显示“扫描已取消”，并提示结果不完整。
- 切到别的页面再切回来，进度和摘要不会退回“尚未扫描”。

## 2. 环境状态卡（T05）

1. 总览页往下看“环境状态”卡。

预期：
- 休眠：显示已启用/未启用。
- 页面文件：列出配置的页面文件路径，没有配置时显示“没有配置页面文件”。
- WSL 发行版：列出名称和位置，没装时显示“没有安装 WSL 发行版”。
- 桌面、文档、下载等目录，以及 OneDrive：标明“已在其他盘 / 在 C 盘”；读不到的项显示“未知”，不影响扫描。
- 这一项全程只读。

## 3. 空间分析与 Top 文件（T03）

1. 进入“空间分析”页，在“目录”页签逐级点进一个子目录，再用面包屑退回。

预期：
- 目录表列出名称、占盘、逻辑大小、文件数、占父目录比例条。
- 无权读取或已跳过的链接有标记，不会显示成 0 字节的正常目录。
- 每行的“打开位置”能在资源管理器里定位到该目录。
- 没有扫描结果时，页面提示先去“总览”页扫描。

2. 切到“Top 文件”页签。

预期：
- 按占盘大小降序列出文件，可以打开位置。

## 4. treemap（T08）

1. 在“空间分析”页切到“图形”页签。

预期：
- 只画当前目录的直接子目录，按占盘大小取前 60 个，其余合并成“其他”。
- 悬停有提示，点击能进入该子目录，面包屑和“目录”页签保持同步。
- 拖动窗口大小，布局跟着重排。
- 只读，不改任何文件。

## 5. 规则候选与只读状态（T04、T05）

1. 进入“清理”页，等评估结束（顶部显示评估耗时）。

预期：
- 分组顺序为 安全 / 谨慎 / 残留 / 手动 / 禁区；禁区默认折叠，只列名称和原因。
- 每行显示名称、占盘大小、状态徽标（可执行、进程运行中：xxx、未找到、布局不符、将在 Mx 开放、证据不足、禁区）、说明和样例路径。
- 进程正在运行的候选标明“请先退出 xxx”，且不能勾选。
- 手动层只有分析结果，没有执行入口。
- 点“重新评估”可以刷新耗时和数字。

## 6. 占用检测（T05）

1. 在任意候选行点“检查占用”，等结果。

预期：
- 有占用时列出占用进程；没有占用时显示“本次未发现占用（检测 x/y 个文件）”。
- 只检查了部分文件或查询出错时，显示“检测不完整：原因”，不能显示成“没有占用”。
- 这一步只读，不会结束任何进程。

## 7. 冻结清单预览（T07、T08）

1. 在安全组勾选任意一个 Ready 的候选（或用“一键清理安全项”进入预览），看“清理预览”。

预期：
- 每条规则一行，带恢复方式标签（可再生 / 永久删除 / 隔离 / 不可撤销命令）、文件数、占盘大小、逻辑大小。
- 有构建时跳过的条目时，可以展开看原因（链接已跳过、无法读取目录、正在运行的程序文件等）。
- 点开某条规则可以分页查看条目，每页 200 条。
- 汇总里逻辑大小、占盘大小、预计可回收三个口径都在，预计可回收带“硬链接或被占用的文件可能不会释放空间”的说明。
- 包含永久删除类规则时必须勾选“我了解这些文件将被永久删除”才能确认；没勾选时确认按钮不可用。
- **先不要点执行**，直接关闭预览，确认没有发生任何删除（C 盘剩余空间不变）。

## 8. 一键清理安全项（T09）

1. 记录 C 盘剩余空间。
2. 在安全组点“一键清理安全项”，看预览，确认清单和体积合理后执行。

预期：
- 执行中显示进度，可以取消；取消时提示“已删除的文件不可恢复”，历史里记为“已取消”。
- 结束后显示每条规则的删除数、跳过数、跳过原因，以及执行前后的剩余空间。
- 执行后自动重新评估，安全组的数字变成清理后的值。
- 实际释放的空间与“预计可回收”大致相符；差额记下来（硬链接、被占用文件会造成差额）。
- 目标应用（浏览器、资源管理器）功能正常，缓存按预期重建。

## 9. 清理谨慎项（T09）

1. 记录 C 盘剩余空间。
2. 在谨慎组勾选一两项（建议先选缩略图缓存这种可再生的项），点“清理选中项”，预览后执行。

预期：
- 只有勾选且可执行的项进入清单，未勾选的不受影响。
- 流程和结果展示与第 8 步一致。
- 谨慎组里默认不勾选的项（例如用户 Temp）保持未勾选。

3. 勾选一个进程正在运行的应用规则（例如已打开的浏览器缓存）。

预期：该项不可勾选，并提示先退出对应进程。

## 10. 清空 C 盘回收站（T09）

1. 先往 C 盘回收站里放几个不重要的文件，记录 C 盘剩余空间。
2. 在谨慎组找到回收站那一行，点“清空回收站”。

预期：
- 确认框写明“将清空执行时 C 盘回收站的全部内容（当前 N 项，X GB），不可恢复”。
- 执行后回收站为空；如果执行前回收站内容变了，提示“回收站内容已变化，请重新确认”并拒绝执行。
- 这一步是独立操作，不产生冻结清单，也不出现在预览里。

## 11. 开发缓存官方命令（T10）

1. 记录 C 盘剩余空间。
2. 在“不可撤销命令”分组里，对 npm 那一行点“运行”。

预期：
- 确认框写明“调用 npm 官方命令，作用范围：<缓存路径>；不可撤销；无法逐文件预览”。
- 运行中显示“运行中…（超时只报告，不会强行终止）”。
- 结束后显示前后缓存大小对比；失败时显示退出码和输出末尾，缓存目录不会被直接删除。

3. 对 uv clean 或 NuGet global-packages 点“运行”。

预期：多一步二次确认，取消二次确认就不执行。

4. 对没安装的工具（例如本机没有 pnpm）看状态。

预期：显示“未安装”，不能运行。缓存路径不在 C 盘的工具显示“缓存不在 C 盘：…”，也会跳过。

## 12. 隔离区与还原（T11）

1. 进入“隔离区”页，看“保存位置”。

预期：
- 下拉框只列固定 NTFS 盘，不含 C 盘（系统盘）和 OneDrive 所在盘。
- 默认选中剩余空间最大的卷，路径形如 `X:\CClearQuarantine`；之后的设置会保存在 `%LOCALAPPDATA%\CClear\settings.json`。

2. 去清理页对任一条残留规则执行“移入隔离区”（若本机没有残留候选，可先做第 13 步准备）。记录 C 盘剩余空间。

预期：
- 预览里该规则标为“隔离（可还原）”。
- 执行后提示去隔离区页查看，清理页的数字重新评估。
- 隔离区批次列表出现新批次：时间、来源规则、条目数、大小、状态（已隔离）、存放天数。

3. 在批次行点“还原”。

预期：
- 原位置的文件回来了，内容和修改时间与原来一致；批次状态变成已还原，副本被清除。
- 原位置已有同名文件时，冲突条目被跳过并列在结果里，不会覆盖。

4. 再隔离一次，然后点“彻底删除”（需确认）。

预期：批次目录从隔离根下消失，确认框写明“批次里的 N 个文件将无法恢复”。

5. 若某个批次状态是“需要处理”，点“处理异常：继续”或“处理异常：放弃”。

预期：继续会逐项复核后接着删源；放弃会删掉副本、保留源文件。

## 13. 残留适配器与隔离（T12）

1. 在清理页的残留组找有候选的规则，点“查看证据”。

预期：展开后列出证据（版本号、路径、判定依据）和说明（notes），能看出为什么选中这些目录；证据不足的规则状态是“证据不足”，不能执行。

2. 点“移入隔离区”，预览后执行，然后去隔离区页确认。

预期：
- 整棵残留目录进入隔离区，源位置消失，批次可以还原。
- 比当前版本更新的残留、正在更新的应用目录不会被选中。

3. 有“需要管理员”标识的行（联想应用商店、NVIDIA App）。

预期：按钮显示“移入隔离区（需管理员）”，执行时弹出一次 UAC；在隔离区里还原或彻底删除这类批次时还会再提权一次。

## 14. 工具缓存目录迁移（T13）

1. 记录 C 盘剩余空间。进入“迁移”页，看“工具缓存目录”区。

预期：表格列出 uv、pip、npm、NuGet、Gradle 的当前路径、大小、是否在 C 盘、状态；CARGO_HOME / RUSTUP_HOME 只给说明文字，没有自动迁移入口。

2. 选一个已安装的工具，选定“迁移旧缓存”或“允许重建”，点“开始迁移”。

预期：
- 有相关进程在运行（node、python、java 等）时先给出警告并要确认。
- 迁移会复制到 `<目标盘>:\CClearData\<工具>` 并校验，然后写入用户级配置，再用新进程运行验证命令确认生效路径已经改变。
- 验证不通过时自动恢复旧配置并报告失败，不会留下半套配置。
- 成功后提示重启 IDE 和终端。

3. 在新终端里运行对应工具的命令，确认缓存路径已经指向新位置（例如 `npm config get cache`）。

预期：路径是 `<目标盘>:\CClearData\npm`；Gradle 会整体迁移 `.gradle`，界面上有整体迁移提示。

4. 点“清理旧目录”，走一次冻结清单预览后执行。

预期：旧缓存目录按清单删除，预览里的条目和体积与迁移前的统计一致。

5. 点“撤销”。

预期：配置恢复成迁移前的值，缓存位置回到原处；旧目录已被清理的工具会在原位置重新生成缓存。状态停在“已记录旧配置”“已写入新配置”“需要处理”或“验证失败”时也能撤销。

6. 选一个工具开始迁移，在验证之前强制结束应用（看到状态变成“已记录旧配置”或“已写入新配置”就可以结束），然后重新打开。

预期：
- 启动时自动把旧配置恢复回去，记录变成“验证失败，已恢复旧配置”，说明里写着“上次迁移在验证前被中断，已恢复原配置”。
- 恢复失败时状态变成“需要处理”，迁移页顶部显示原因，“撤销”按钮仍然可用。

## 15. 提权 helper 与 ProgramData 残留（T14）

1. 记录 C 盘剩余空间。
2. 对带“需要管理员”的 ProgramData 残留执行清理，在 UAC 提示里点“是”。

预期：
- 只弹一次 UAC，helper 执行完自动退出，不出现第二个窗口。
- 结果回到主界面，条目进入隔离区，批次带“需要管理员”标记。
- helper 的日志写在 `%ProgramData%\CClear\journal\<日期>.jsonl`。

3. 再执行一次，在 UAC 提示里点“否”。

预期：显示“已取消授权”，没有任何文件被改动。

## 16. 系统维护（T15）

1. 记录 C 盘剩余空间。
2. 在“系统维护（需要管理员）”分组点“分析组件存储（只读）”，按提示授权。

预期：返回 Actual Size、Reclaimable Packages、Cleanup Recommended 三项，这一步不改动组件存储。

3. 勾选 Windows\Temp、Windows\Logs 等文件类项，点“执行选中项”，一次授权。

预期：
- 整个过程中只弹一次 UAC。
- 每一项单独报告结果；被占用的文件跳过，不会强行终止进程。
- 执行前后显示剩余空间变化。

4. 勾选“组件存储清理（DISM）”再执行。

预期：确认框写明可能需要 10–30 分钟且无法取消、请勿关机；执行中按百分比显示进度；命令里没有 `/ResetBase`。

## 17. 目录迁移与迁回（T16）

1. 记录 C 盘剩余空间。在“空间分析”页选一个纯数据目录（不含 exe/dll、不含链接），点“迁移到其他盘…”。

预期：跳到迁移页的“目录迁移”区，显示资格检查结果；不合格的目录给出拒绝原因（位于 AppData\Local\Microsoft、Packages、OneDrive 同步目录下，是桌面/文档/图片/音乐/视频/保存的游戏/AppData\LocalLow 这些已知文件夹本身，或目录内含 exe、链接、只读文件、加密文件、云占位文件等）。

2. 选目标卷，点“开始迁移”。

预期：
- 步骤时间线依次推进：预检 → 复制 → 校验 → 源改名 → 创建 junction → 校验 → 等待实测。
- 目标路径为 `<目标盘>:\CClearMig\<8 位 id>`，源目录改名为 `<目录名>.cclear-bak-<id>`，原位置变成 junction。
- 状态进入“等待实测”，界面提示打开相关应用确认正常。

3. 打开对应应用确认功能正常，然后点“确认删除备份”。

预期：备份目录被删除，状态变成完成；C 盘剩余空间增加约等于目录大小。完成后“迁回”仍然可用。

4. 点“迁回”。

预期：
- 复制前检查来源盘的剩余空间够不够（不够会直接拒绝）；来源盘上出现临时目录 `<目录名>.cclear-return-<id>`，复制并校验通过后才移除 junction、改名回原名。
- 复制前后各核对一次目标目录：目标里没有进程占用、内容没有变化才继续，否则删掉临时目录并提示“目标目录仍在被使用或发生了变化，请关闭相关程序后重试”。
- 迁移之后经 junction 写入的新文件，迁回后仍然存在（以目标里的最新数据为准）；空目录也一起回来。
- 迁回后由用户单独确认是否删除目标盘上的旧副本。

5. 迁移过程中强制结束应用，重新打开。

预期：启动时的恢复逻辑给出确定状态——只复制了一半的目标副本被清理，源目录回到原名；已经建立 junction 的条目进入“需要处理”，由界面提供“继续”或“迁回”；建链接中途中断留下的空目录会被删掉再改名回原名，非空目录则保留给人判断。

6. 迁回过程中强制结束应用（状态显示为“正在迁回”），重新打开。

预期：
- 原位置还是 junction 时，临时目录被删掉，记录回到“等待确认应用正常”（备份已删的回到“完成”），链接和数据都没有变化。
- 原位置已经没有链接、临时目录完整时，临时目录被改名回原名，记录记为“已迁回”。
- 其他现场记成“需要处理”，说明里写清原位置、目标和临时目录各自是否存在。

## 18. 历史（T08、T09）

1. 进入“历史”页。

预期：
- 列表列为时间、规则、释放空间、跳过数，只显示最近 30 天的记录。
- 点某条记录看“清理详情”，能看到逐条结果和跳过原因，以及执行前后的剩余空间。
- 被取消的执行显示为“已取消”，不是“已正常结束”。
- 日志文件在 `%LOCALAPPDATA%\CClear\journal\<日期>.jsonl`，可以被正常读取。

## 19. 打包与安装（T17）

1. 按 README 构建：先设置 `$env:CARGO_TARGET_DIR`，再 `npm ci`、`npm run tauri build`。

预期：
- 生成的可执行文件在 `$env:CARGO_TARGET_DIR\release\cclear.exe`。
- 生成 NSIS 安装包，`bundle.targets` 为 `["nsis"]`，`bundle.windows.nsis.installMode` 为 `"currentUser"`。
- 构建过程不联网下载额外组件（首次 `npm ci` 和 cargo 拉取依赖除外）。

2. 用安装包安装并启动。

预期：
- 安装过程不弹 UAC，按当前用户安装。
- 启动后界面文字全部为中文，大小显示为 `x.xx GB / MB`。
- 主程序清单仍是 asInvoker：任务管理器里以普通权限运行。
- 卸载程序不会强制删除 `%LOCALAPPDATA%\CClear` 里的日志和设置（`deleteAppDataOnUninstall` 保持默认关闭，这是应用数据，不是安装目录）。
