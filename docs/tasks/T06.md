# T06 路径护栏 guard

- 里程碑：M2
- 依赖：T05

## 目标
实现全项目唯一的破坏性文件操作入口：基于句柄逐级相对打开路径，复核文件身份后再按句柄删除，从根本上避免“检查之后、使用之前路径被替换”的竞态（TOCTOU）。这是 P0 安全模块。

## 实现要点
```rust
pub struct Forbidden { pub ids: HashSet<FileIdentity>, pub names: Vec<String> }
impl Forbidden { pub fn from_rules(roots: &RootMap) -> Self /*把存在的禁区目录打开取 identity；names 来自 forbidden_names*/ }
pub struct DirHandle { /* OwnedHandle + FileIdentity + 规范路径 */ }
pub enum OpenIntent { Inspect, Delete }
pub struct Entry { pub identity: FileIdentity, pub is_dir: bool, pub size: u64, pub allocated: u64, pub attributes: u32, pub ctime: u64, pub mtime: u64, /* handle */ }
pub struct Expect { pub identity: FileIdentity, pub size: u64, pub mtime: u64 }
pub enum GuardError { ReparseInPath(PathBuf), Forbidden(PathBuf), Changed, Gone, Locked, Denied, ReadOnly, DirNotEmpty, InvalidName, Io(io::Error) }
pub fn open_anchor(path: &Path, forbidden: &Forbidden) -> Result<DirHandle, GuardError>;
pub fn open_rel(anchor: &DirHandle, rel: &[OsString], intent: OpenIntent, forbidden: &Forbidden) -> Result<Entry, GuardError>;
pub fn list_dir(anchor: &DirHandle, rel: &[OsString], forbidden: &Forbidden) -> Result<Vec<EntryInfo>, GuardError>;
pub fn delete(entry: Entry, expect: &Expect) -> Result<(), GuardError>;
```
1. `open_anchor`：用 `CreateFileW` 打开卷根 `\\?\X:\`（带 `FILE_FLAG_BACKUP_SEMANTICS`），然后**逐个组件**相对父句柄打开。规则如下：
   - 任一组件是 reparse point → `ReparseInPath`
   - 任一组件的 identity ∈ `forbidden.ids`，或组件名 ∈ `forbidden.names` → `Forbidden`
   - 因为按 identity 比较，8.3 短名和大小写差异无法绕过禁区
2. 相对打开使用 `windows::Wdk::Storage::FileSystem::NtCreateFile`：
   - `OBJECT_ATTRIBUTES.RootDirectory` = 父句柄，ObjectName = 单个组件名，属性 `OBJ_CASE_INSENSITIVE`
   - CreateOptions = `FILE_OPEN_REPARSE_POINT | FILE_SYNCHRONOUS_IO_NONALERT`，再加 `FILE_DIRECTORY_FILE` 或 `FILE_NON_DIRECTORY_FILE`
   - Disposition = `FILE_OPEN`
   - 中间组件只申请 `FILE_LIST_DIRECTORY | FILE_TRAVERSE | FILE_READ_ATTRIBUTES | SYNCHRONIZE`
   - 最后一个组件在 `Delete` 意图下申请 `DELETE | FILE_READ_ATTRIBUTES | SYNCHRONIZE`，共享模式为读/写/删全部共享
   - 组件名包含 `\ / :`、为空、或者是 `.`、`..` 时返回 `InvalidName`
3. `delete`：
   - 先用同一个句柄的 `FileIdInfo` 和 `FileBasicInfo`/`FileStandardInfo` 复核 identity、size、mtime，不一致返回 `Changed`
   - 带只读属性的返回 `ReadOnly`，**不清除属性，也不使用 IGNORE_READONLY 标志**
   - 最后一个组件本身是 reparse point 时一律拒绝（返回 `ReparseInPath`）
   - 删除方式：`SetFileInformationByHandle(FileDispositionInfoEx, FILE_DISPOSITION_FLAG_DELETE | FILE_DISPOSITION_FLAG_POSIX_SEMANTICS)`
   - 错误映射：共享冲突、锁冲突 → `Locked`；拒绝访问 → `Denied`；目录非空 → `DirNotEmpty`；找不到 → `Gone`
4. `list_dir` 复用 `win::dirinfo::for_each_entry`，但目录句柄通过 `open_rel` 获得。
5. 所有 unsafe 块都要写 `// SAFETY:` 注释。

## 必须编写的测试（`tests/guard.rs`，全部在 tempdir 中；测试里用 `cmd /c mklink /J` 创建 junction）
1. 基本删除：锚点内的文件删除成功，同级的哨兵文件仍在。
2. 祖先被替换：先记录 `anchor\a\b\f` 的 Expect；然后把 `a` 改名，并在原位置创建 junction 指向外部目录（外部目录里有同名的 `b\f` 哨兵）。`open_rel` 返回 `ReparseInPath`，哨兵内容不变。
3. 同名替换：删除前把 `f` 删掉并重建同名文件，`delete` 返回 `Changed`，新文件仍在。
4. 硬链接：锚点内的 `f` 与锚点外的 `g` 互为硬链接，删除 `f` 后 `g` 的内容不变。
5. 只读文件：返回 `ReadOnly`，文件仍在且属性未被修改。
6. 被占用：测试进程以不共享 DELETE 的方式打开文件，`delete` 返回 `Locked`。
7. 长路径：路径超过 300 字符的文件可以删除。
8. 禁区：把 tempdir 中的目录 X 加入 `Forbidden.ids` 后，`open_anchor(X\sub)` 返回 `Forbidden`；卷支持 8.3 短名时，用短名路径也会被拒绝（`GetShortPathNameW` 没有返回短名时跳过这个断言）。
9. 非空目录：删除返回 `DirNotEmpty`。
