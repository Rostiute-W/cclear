# T16 junction 目录迁移与迁回

- 里程碑：M6
- 依赖：T15

> 执行者先阅读仓库根目录的 `AGENTS.md`。本文件之外的需求一律不做。

## 目标
把纯数据目录迁移到其他盘，在原位置留下 junction。全过程有状态机、可恢复，迁回时以目标盘中的最新数据为准。

## 实现要点
1. guard 新增：
   - `rename_child(parent: &DirHandle, from, to, expect)`：同目录内改名，使用 `FileRenameInfoEx` + POSIX 语义，不替换已存在的目标。
   - `create_junction(parent: &DirHandle, name, target_abs: &Path)`：先用 `NtCreateFile` 以 `FILE_CREATE` 相对创建空目录，再调用 `FSCTL_SET_REPARSE_POINT` 写入 MountPoint 数据（SubstituteName 为 `\??\X:\CClearMig\<id>`，PrintName 为 `X:\CClearMig\<id>`）。
   - `read_junction_target(parent, name)`。
   - `remove_junction(parent, name, expect_target)`：用 `FILE_OPEN_REPARSE_POINT` 打开，校验 tag 为 `IO_REPARSE_TAG_MOUNT_POINT` 且目标与 expect_target 一致后，删除链接本身。
2. `migrate/junction.rs` 的资格检查：
   - 源路径来自扫描结果的节点 ID（经过 `validate_external_path`），并且必须位于 Profile 之下。
   - 不能是 Profile 本身，也不能是 AppData、Local、Roaming、Documents 等 Known Folder 的根目录。
   - 不能落在 forbidden 内，也不能在 `AppData\Local\Packages`、`AppData\Local\Microsoft` 或 OneDrive 下。
   - 目录内不能含 reparse point、`.exe` / `.dll` 文件、EFS 文件或云占位符。
   - 检查结果以原因列表的形式返回。
3. 目标路径为 `<X>:\CClearMig\<8 位十六进制 id>`，卷必须是固定 NTFS、非 C 盘，且目标路径之前不存在。
4. 状态机（持久化在 `migrations.json`，并写日志）：`Precheck → Copying → Verified → SourceRenamed → JunctionCreated → Validated → AwaitingUserTest → BackupDeleted → Done`。
   - Verified 之后再次检查：映像路径位于源目录下的进程、源目录前 256 个文件的 Restart Manager 结果、源快照（identity、size、mtime）与复制时一致。不满足时中止，删除目标副本。
   - 把源目录改名为 `<name>.cclear-bak-<id>`，然后在原名位置创建 junction，再经 junction 读取 3 个文件并比对哈希。
   - 进入 AwaitingUserTest 状态，界面提示“请打开相关应用确认正常”。用户确认后，以备份目录为锚点构造临时规则，走冻结清单删除备份。
5. 迁回（任何已经创建了 junction 的状态都走同一条路径）：
   1. 检查 C 盘剩余空间 ≥ 目标逻辑大小 + 2 GiB
   2. 把目标复制到 `<name>.cclear-return-<id>` 并校验
   3. `remove_junction`
   4. 把 return 目录改名回原名
   5. 如果备份还在，由用户确认后删除；目标副本同样由用户确认后删除
6. `recover_pending()`：
   - Copying 状态：删除目标副本
   - SourceRenamed 状态（还没有 junction）：把源改回原名，并删除目标副本
   - 其他状态：标记 NeedsAttention，由界面提供“继续”或“迁回”
7. 界面：
   - 空间分析页的目录行增加“迁移到其他盘…”，只传节点 ID
   - 迁移页新增“目录迁移”区：资格检查结果、目标卷选择、步骤时间线、当前状态，以及“确认删除备份”“迁回”按钮

## 不要做
不迁移程序目录，不调用 `cmd mklink`，不自动删除备份。

## 必须编写的测试（`tests/junction.rs`；为测试允许同卷，相关参数通过注入提供）
1. 完整迁移：目标内容一致，原路径变为 junction，经 junction 能读到内容；确认删除备份后，备份目录消失。
2. 迁回：迁移后经 junction 写入一个新文件；迁回后原路径是普通目录且包含这个新文件，junction 已被移除。
3. 资格拒绝：含 .exe 的目录、含 junction 的目录、位于 Packages 下的路径（通过 RootMap 模拟）都被拒绝。
4. 中途失败恢复：在 SourceRenamed 之后模拟中断，`recover_pending` 把源改回原名并删除目标副本。
