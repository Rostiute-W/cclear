# T02 扫描器

- 里程碑：M1
- 依赖：T01

> 执行者先阅读仓库根目录的 `AGENTS.md`。本文件之外的需求一律不做。

## 目标
在 core 中实现并行目录扫描器。统计口径：占盘大小、逻辑大小、硬链接去重、不跟随 reparse point、拒绝访问可见。

## 实现要点
1. `win/dirinfo.rs`：
   - `open_dir(path) -> io::Result<OwnedHandle>`：调用 `CreateFileW`，访问权限 `FILE_LIST_DIRECTORY | SYNCHRONIZE`，共享模式读/写/删全部共享，`OPEN_EXISTING`，标志 `FILE_FLAG_BACKUP_SEMANTICS | FILE_FLAG_OPEN_REPARSE_POINT`。路径先经过 `win::to_verbatim` 转成 `\\?\` 形式。
   - `for_each_entry(handle, f)`：调用 `GetFileInformationByHandleEx`，第一次用 `FileIdExtdDirectoryRestartInfo`，之后用 `FileIdExtdDirectoryInfo`。缓冲区 64 KiB、按 8 字节对齐，按 `NextEntryOffset` 解析，遇到 `ERROR_NO_MORE_FILES` 结束，跳过 `.` 和 `..`。产出 `EntryInfo { name: OsString, file_id: u128, logical: u64 (EndOfFile), allocated: u64 (AllocationSize), attributes: u32, reparse_tag: u32, creation_time: u64, last_write_time: u64 (FILETIME), is_dir: bool }`。
   - `volume_serial(handle) -> u64`：用 `FileIdInfo` 获取。
2. `model.rs`：定义 `SizeInfo { logical, allocated, files, dirs }` 和 `FileIdentity { volume_serial: u64, file_id: u128 }`（Hash、Eq、serde）。
3. `scan/` 的公共 API：
```rust
pub struct ScanOptions { pub threads: usize /*默认 min(8, CPU 数)*/, pub top_files: usize /*默认 500*/,
    pub file_filter: Option<Arc<dyn Fn(&EntryInfo) -> bool + Send + Sync>> }
pub struct ScanProgress { pub dirs: AtomicU64, pub files: AtomicU64, pub allocated: AtomicU64 }
pub struct DirNode { pub id: u32, pub parent: Option<u32>, pub name: String, pub size: SizeInfo /*含整个子树*/,
    pub children: Vec<u32>, pub denied: bool, pub reparse_skipped: u32, pub cloud_files: u32 }
pub struct FileEntry { pub path: PathBuf, pub logical: u64, pub allocated: u64, pub last_write_time: u64 }
pub struct ScanResult { pub roots: Vec<u32>, pub nodes: Vec<DirNode>, pub top_files: Vec<FileEntry>,
    pub denied_dirs: u64, pub elapsed_ms: u64, pub cancelled: bool }
pub fn scan(roots: &[PathBuf], opts: &ScanOptions, progress: &ScanProgress, cancel: &AtomicBool) -> Result<ScanResult>
impl ScanResult { pub fn path_of(&self, id: u32) -> PathBuf; pub fn children_by_size(&self, id: u32) -> Vec<&DirNode> /*按 allocated 降序*/ }
```
4. 规则：
   - 带 `FILE_ATTRIBUTE_REPARSE_POINT` 的目录不进入，`reparse_skipped += 1`，大小不计入。
   - 带 reparse 的文件：云占位符（属性 `RECALL_ON_DATA_ACCESS` / `RECALL_ON_OPEN` 或 tag 为 `IO_REPARSE_TAG_CLOUD*`）按 allocated 计入，并 `cloud_files += 1`；`IO_REPARSE_TAG_DEDUP` 正常计入；其他类型（符号链接、AppExecLink 等）不计入。
   - 打开目录失败时设置 `denied = true`，然后继续扫描其他目录。
   - 硬链接去重：用全局分片的 `HashSet<(volume_serial, file_id)>`（例如 64 个分片），同一个文件只计一次大小和一次文件数。
   - 并行：用 rayon，按目录粒度分发任务。线程池大小取 `threads`。
   - `top_files`：每个线程维护一个有界最小堆，最后合并。
   - 取消：每处理一个目录检查一次 `cancel`，返回已扫描的部分结果，并设置 `cancelled = true`。
   - 子树大小在最后自底向上汇总。
5. `file_filter` 返回 false 的文件不计入任何统计，T04 用它统计规则子集的大小。

## 必须编写的测试（`crates/cclear-core/tests/scan.rs`，全部在 tempdir 中进行）
1. 硬链接：1 MiB 的文件和它在另一个子目录中的硬链接，根目录的 logical 只计 1 MiB，files = 1。
2. junction 不跟随：根目录下有 A（含 1 MiB 文件）和 junction J→A，大小只计一次，并且 `reparse_skipped >= 1`。
3. 长路径和中文：路径总长超过 300 字符、目录名含中文的文件能被计入，`path_of` 返回正确的路径。
4. `file_filter`：按文件名排除的文件不计入。
