## 目标
通过官方命令清理 npm、pnpm、pip、uv 和 NuGet 的缓存。失败就跳过，绝不退回直接删除目录。

## 实现要点
1. `exec/command.rs`：
   - `resolve_tool_in(name, path_var: &OsStr) -> Option<PathBuf>`：按 PATH 中目录的顺序查找，在同一个目录内依次尝试 `.exe`、`.cmd`、`.bat`，忽略 `.ps1`。
   - `resolve_tool(name)`：使用当前进程的 PATH 调用上面的函数。
   - `run(tool: &Path, args: &[&str], timeout: Duration) -> CmdOutcome { exit_code: Option<i32>, timed_out: bool, stdout_tail: String, stderr_tail: String /*各保留最后 4 KiB*/ }`
     - `.cmd` 和 `.bat` 通过 `<System32>\cmd.exe /d /c` 执行，参数只使用内置常量
     - 设置 `CREATE_NO_WINDOW`，stdin 为 null
     - 超时后**不杀进程**，返回 `timed_out = true`
2. 命令表放在 `rules/commands.rs`，所有调用都通过 `exec::command::run`：

| CommandId | 工具 | 查询缓存路径 | 清理 | 超时 | 需要二次确认 |
|---|---|---|---|---|---|
| NpmCache | npm | `config get cache` | `cache clean --force` | 600s | 否 |
| PnpmStore | pnpm | `store path` | `store prune` | 600s | 否 |
| PipCache | pip | `cache dir` | `cache purge` | 600s | 否 |
| UvPrune | uv | `cache dir` | `cache prune` | 900s | 否 |
| UvClean | uv | `cache dir` | `cache clean` | 900s | 是 |
| NugetHttp | dotnet | `nuget locals http-cache --list` | `nuget locals http-cache --clear` | 600s | 否 |
| NugetTemp | dotnet | `nuget locals temp --list` | `nuget locals temp --clear` | 600s | 否 |
| NugetGlobal | dotnet | `nuget locals global-packages --list` | `nuget locals global-packages --clear` | 900s | 是 |

   - 查询命令的超时为 30s；NuGet 的输出格式为 `xxx: <path>`。
   - 评估结果：工具没装 → `NotPresent("未安装")`；路径不在 C 盘（按卷序列号比较）→ `Insufficient("缓存不在 C 盘：…")`；否则统计该路径的大小。
   - 执行后重新统计大小，报告前后对比，并写日志 `Record::CommandRun`（退出码、是否超时、前后大小）。
   - 这些规则的 Recovery 是 `IrreversibleCommand`，`ENABLED_PHASES` 已经包含 M3b。
3. 命令 `command_execute(ruleId, secondConfirm: bool, onProgress)`：需要二次确认的规则在 `secondConfirm = false` 时拒绝执行。
4. 清理页新增“不可撤销命令”分组。每行有单独的“运行”按钮，确认对话框写明：“调用 xxx 官方命令，作用范围：<路径>；不可撤销；无法逐文件预览”。需要二次确认的规则多一步确认。运行中显示“运行中…（超时只报告，不会强行终止）”。

## 不要做
不调用 cargo-cache，不在失败后删除目录，不提权。
