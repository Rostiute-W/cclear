## 目标
修复检查点 D 审查中 T13（工具缓存目录迁移）和 T16（junction 迁移与迁回）的问题。原则：迁移任何一步失败或中断，源数据都必须完整可用；界面上每个中间状态都要有可用的操作。

## 实现要点

### A. junction 迁回（P1）
1. 迁移完成后可以迁回：`migrate/junction.rs:185-194` 的 `has_junction()` 加入 `Done`。`return_home`（640 行）仍然同时要求 `source_is_junction`。
2. 迁回前的空间检查查 C 盘：`junction.rs:653` 的 `(self.free_space)(&source)` 中 `source` 是指向目标盘的 junction，`GetDiskFreeSpaceExW` 会跟随它，得到的是目标盘的剩余空间（Droid 已实测）。改为查询 `parent_of(&source)`（来源盘上的普通目录）。
3. 迁回增加持久化的中间状态 `Returning`（加入 `DirStage`，界面显示“正在迁回”），复制开始前保存。
4. 迁回的复制失败时，通过 guard 删除 `<name>.cclear-return-<id>` 临时目录，再返回错误；状态回到迁回前的状态。
5. 迁回复核：复制前先做进程/占用检查（复用 `check_stable`），复制前后对目标做 `snapshot` 比对；有变化或有进程在用就删除临时目录、拒绝迁回，提示“目标目录仍在被使用或发生了变化，请关闭相关程序后重试”。
6. 删除 junction 成功但改名失败时：不要删除临时目录（`junction.rs:686-688` 现在会删）。先尝试用 `guard::create_junction` 重建原 junction；重建成功则删除临时目录，状态回到迁回前；重建失败则保留临时目录，状态记为 `NeedsAttention`，说明里写明临时目录的完整路径。
7. `recover_pending` 处理 `Returning`：原位置是 junction → 删除临时目录（若存在），回到 `AwaitingUserTest`（或 `Done`，按记录中是否已删备份）；原位置不存在且临时目录完整 → 改名回原名，记为 `Returned`；其他情况记为 `NeedsAttention` 并写明现场。

### B. junction 迁移的其他缺陷（P1）
8. `Verified` 中断后要恢复：`recover_pending`（747-793）对 `Verified` 按 `Copying` 处理（删除目标副本，记为 `Failed`，源目录完好）。
9. 空目录：`collect_files`（1053-1086）、`snapshot` 和复制（`copy_tree` 845-861，以及 T17a 补过的 `copy_tree_verified`）都要包含目录；复制时创建所有目录（含空目录），复核时比对目录集合。迁回同样适用。
10. 只读文件：资格检查遇到含只读属性文件的目录时拒绝迁移，原因“目录里有只读文件，CClear 不修改只读属性，无法保证出错时能清理干净”。
11. `recover_pending` 中单条记录出错时把该记录记为 `NeedsAttention` 并继续处理下一条，不要用 `?` 中断；`src-tauri/src/commands/migrate.rs` 中 `recover_on_startup` 不要 `let _ =` 吞掉错误，把错误和恢复结果交给界面显示（沿用现有启动恢复的展示方式）。
12. `NeedsAttention` 而 junction 已存在时允许“继续”：重新校验 junction 指向目标、目标与备份内容一致后进入 `AwaitingUserTest`。`resume`（501-504）不要只接受源不存在的情况。
13. 只有经过 `Validated` 的记录才允许删除备份：记录中增加“已验证”标记，`backup_plan`（544-546）对 `NeedsAttention` 也要检查这个标记，未验证的拒绝。
14. 建 junction 中途崩溃：恢复时如果原位置是一个**空的普通目录**且备份目录存在，先通过 guard 删除这个空目录（只删空目录，非空就记为 `NeedsAttention`），再改回原名。
15. 删除备份的执行（`commands/migrate.rs:392-400`）传 `Forbidden::from_rules(&roots)` 和 `running_processes()`，不要传空集合。
16. `guard::rename_child`（`guard/path.rs:271-290`）对共享冲突和拒绝访问做退避重试：最多 3 次，间隔 200、500、1000 毫秒（plan-final 第 7 节要求，用于应对杀软临时锁）。
17. 拦截更多 Known Folder 根：`junction.rs:949-963` 补上 Desktop、Pictures、Music、Videos、`AppData\LocalLow`、Saved Games（都用 `win::known_folder` 解析）；Profile 下名字以 `OneDrive` 开头的目录（含 “OneDrive - 公司名”）都拒绝。

### C. 工具缓存目录迁移（T13，P1）
18. 中断后可撤销：`Migrate.tsx:35` 的 `REVERTIBLE_STAGES` 加入 `planned`、`configured`、`failed`；后端 `revert` 对这些阶段用记录的旧值恢复（旧值为空表示原来没有该变量，恢复时删除）。
19. 启动恢复：`recover_on_startup` 同时处理工具迁移记录，`Planned`/`Configured` 的记录自动恢复旧值并记为 `Failed`（说明“上次迁移在验证前被中断，已恢复原配置”）；恢复失败的记为 `NeedsAttention` 类状态，界面显示原因并保留撤销按钮。
20. `start`（`migrate/mod.rs:334-350`）：同一工具已有未撤销的记录（非 `Reverted` 且非已恢复的 `Failed`）时拒绝开始，提示先撤销；任何情况下都不要覆盖已有记录的 `old_values`、`old_paths`。
21. Gradle 只允许“迁移”模式：`tools.rs` 中 Gradle 标记为不支持“允许重建”，`Migrate.tsx:265` 对它禁用该选项；修正 `tools.rs:143-146` 的警告文字。
22. 清理旧目录前校验范围：`start` 时拒绝以下旧路径（不允许迁移，提示原因）：盘符根目录；任一 Known Folder 本身或其祖先（Profile、LocalAppData、RoamingAppData、Documents、Downloads、ProgramData、Windows 等）；目标目录或其祖先；`<卷>\CClearData` 及其下的路径。`cleanup_plan`（451-457）再检查一次：锚点是当前生效目录或目标目录的祖先或后代时排除（逐组件不区分大小写比较，不只比较相等）。
23. npm 默认缓存路径改为 `KnownRoot::LocalAppData` 下的 `npm-cache`（`tools.rs:102-103`；本机 `npm config get cache` 返回 `%LOCALAPPDATA%\npm-cache`）。
24. 清理旧目录的清单带上该工具的进程名，执行器执行前复核（`OLD_CACHE_RULE_ID` 不在规则目录中，现在 `executor.rs:477-480` 返回空进程列表）。
25. `save_store`（`mod.rs:1056-1064`）和 `junction.rs` 的 `save_one`：如果不是“写临时文件 → `sync_all` → `guard::replace_in_dir`”，改成这样；同时保留上一版为 `migrations.json.bak`，主文件读取失败时读备份并在界面提示。

### D. 文档
