# T12 残留（leftover）适配器

- 里程碑：M4
- 依赖：T11

> 执行者先阅读仓库根目录的 `AGENTS.md`。本文件之外的需求一律不做。

## 目标
为每类多版本残留实现基于证据的判定，判定为残留的内容默认进入隔离区。

## 实现要点
1. `rules/adapters/mod.rs`：
```rust
pub struct LeftoverItem { pub anchor: PathBuf, pub rel: Vec<OsString>, pub is_dir: bool, pub evidence: Vec<String> }
pub struct AdapterResult { pub status: CandidateStatus, pub items: Vec<LeftoverItem>, pub notes: Vec<String> }
pub trait VersionProbe { fn file_version(&self, exe: &Path) -> Option<String>; } // 生产实现基于 GetFileVersionInfoW 和 VS_FIXEDFILEINFO，格式为 "major.minor.build"
pub fn evaluate_adapter(id: AdapterId, roots: &RootMap, procs: &[ProcInfo], probe: &dyn VersionProbe, now: SystemTime) -> AdapterResult;
```
   - 开始编码前，可以**只读**查看本机真实目录来确认文件格式（`LatestInstall.info`、`.obsolete`、`extensions.json`、`product.json`），但不得写入任何内容。确认的格式要写在代码注释中。
2. 各适配器的判定规则（任何一项证据不满足时返回 `Insufficient(原因)`，宁可不选，也不要误选）：
   - **CodexRuntimes**（Profile `.cache\codex-runtimes`）：
     - 必须存在 `codex-primary-runtime`
     - `codex.exe`、`codex-code-mode-host.exe` 在运行时返回 ProcessRunning
     - 候选：所有 `codex-primary-runtime.previous-*` 目录；以及 max(ctime, mtime) 超过 24 小时、并且早于 primary 的 mtime 的 `codex-runtime-install-*` 目录
     - 比 primary 新的 install 目录不选，并在 notes 中说明
   - **VscodeVersions**（LocalAppData `Programs\Microsoft VS Code`）：
     - 存在 `updating_version`、`new_Code.exe` 或 `bin\new_code.cmd` 时返回 `Insufficient("VS Code 更新进行中")`
     - 用 probe 读取 `Code.exe` 的版本
     - 子目录中凡是含 `resources\app\product.json` 的，都读取其中的 version 和 commit；version 等于 Code.exe 版本的目录必须恰好有 1 个，否则返回 Insufficient
     - 候选：其余的 commit 目录，以及 `old_Code.exe`
     - 进程：`Code.exe`
   - **EditorExtensions**（VS Code 一条：Profile `.vscode\extensions`，进程 `Code.exe`；Cursor 一条：Profile `.cursor\extensions`，进程 `Cursor.exe`）：
     - 解析 `.obsolete`（JSON 对象，键为目录名）和 `extensions.json`（取 relativeLocation）
     - 候选：在 `.obsolete` 中、目录确实存在、且没有被 `extensions.json` 引用的目录；以及名称形如 `.<十六进制或连字符，长度≥8>`、超过 24 小时、且未被引用的临时目录
     - `.obsolete` 解析失败时返回 Insufficient
   - **MathworksServiceHost**（LocalAppData `MathWorks\ServiceHost`）：
     - 从 `LatestInstall.info` 中取最新安装路径（按实际格式解析）
     - 候选：除最新版本以外的 `v*` 目录
     - 进程：`MathWorksServiceHost.exe`
     - 解析失败时返回 Insufficient
   - **DroidOld**（Profile `bin`）：必须存在 `droid.exe`；候选：`droid.exe.old-*` 文件。
   - **UpdaterInstallers**：
     - LocalAppData 下的 `qianfan-desktop-app-updater\installer.exe`：没有任何运行中进程的映像路径位于该目录下时才作为候选
     - LocalAppData 下的 `Temp\DockerDesktopUpdates`：`Docker Desktop.exe`、`com.docker.backend.exe`、`Docker Desktop Installer.exe` 都不在运行时才作为候选
   - **WslUnregisteredVhdx**（manual，只做分析）：列出 LocalAppData 下 `wsl\*\ext4.vhdx` 中不在 Lxss 任何 BasePath 里的文件，evidence 写明大小、修改时间、“未在当前用户 WSL 注册表中找到关联”。
3. `ENABLED_PHASES` 加入 M4。`plan_build` 支持 `Target::Adapter` 的 leftover 规则：把适配器返回的条目展开成 FrozenItem（目录展开为整棵子树），Recovery 为 Quarantine，执行时由隔离引擎处理。
4. 清理页的残留组：每个候选展示证据列表和 notes，按钮为“移入隔离区”（经过 PlanPreview，标签为“隔离（可还原）”），执行后提示去隔离区页查看。

## 不要做
不实现 WPS 多版本、未关联 vhdx 的执行；不按“只保留最新版本”这类启发式规则做判断。

## 必须编写的测试（`tests/adapters.rs`，RootMap 注入 tempdir，进程列表和 VersionProbe 注入）
1. CodexRuntimes：primary 保留，previous-* 被选中，比 primary 新的 install-* 不选。
2. VscodeVersions：存在 `updating_version` 时返回 Insufficient；没有时只选中版本不匹配的 commit 目录。
3. EditorExtensions：只选中在 .obsolete 中且未被 extensions.json 引用的目录。
4. MathworksServiceHost：LatestInstall.info 指向的版本被保留，其余 `v*` 被选中。
