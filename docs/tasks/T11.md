# T11 隔离区事务引擎与隔离区页

- 里程碑：M4
- 依赖：T10

> 执行者先阅读仓库根目录的 `AGENTS.md`。本文件之外的需求一律不做。

## 目标
实现可还原的隔离：复制 → 校验 → 删除源。整个过程是持久化的状态机，崩溃后可以恢复。

## 实现要点
1. 隔离根目录：
   - `candidate_volumes(source_volume)`：固定 NTFS 卷中排除系统卷和源卷，再排除 OneDrive 所在路径。
   - 默认选剩余空间最大的卷，保存到 `<LocalAppData>\CClear\settings.json` 的 `quarantineRoot`（形如 `G:\CClearQuarantine`）。
   - 首次创建根目录时用 `win/acl.rs` 设置受保护 DACL：`D:P(A;OICI;FA;;;SY)(A;OICI;FA;;;BA)(A;OICI;FA;;;<当前用户 SID>)`。
2. 批次目录结构：`<root>\<batchId>\manifest.json` 和 `<root>\<batchId>\data\<anchorIndex>\<rel...>`。
   - manifest 记录每个条目的原始锚点、rel、identity、size、mtime、ctime、blake3 哈希和条目状态。
   - manifest 必须原子更新：先写临时文件，再通过新增的 `guard::replace_in_dir(dir: &DirHandle, tmp_name, final_name)`（`FileRenameInfoEx`，带 `FILE_RENAME_FLAG_REPLACE_IF_EXISTS | POSIX_SEMANTICS`）替换。
3. 批次状态：`Planned → Copying → CopiedVerified → DeletingSource → Committed`，以及 `Restoring → Restored`、`Purging → Purged`、`Aborted`、`NeedsAttention`。每次状态变化都写 manifest 和日志（新增 `Record::Quarantine*` 变体）。
4. 隔离流程：
   - 预检：拒绝 EFS 加密文件；reparse 条目已在 plan 阶段排除。
   - 容量：目标卷剩余空间 ≥ Σ逻辑大小 + 2 GiB，否则整批拒绝。
   - 复制：用 `std::fs::copy`（在 Windows 上即 CopyFileExW，保留属性、ADS 和 mtime），再补设 creation time。目标文件已存在时报错，不覆盖。
   - 每复制 256 MiB 检查一次空间，剩余低于 1 GiB 时停止并回滚：删除已复制的副本，源保持不动。
   - 复制完成后用 blake3 分别计算源和副本的哈希，比对一致。
   - 删除源：用 `guard::open_rel(Delete)` + `delete(Expect)` 复核后删除。复核不一致时，该条目标记为“源已变化，源和副本都保留”，批次最终状态为部分完成。
   - 提供 `copy_tree_verified(src_anchor, rel_items, dst, ...)`，这个公共函数会被 T13、T16 复用。
5. `recover_pending()`：应用启动时调用。
   - `Copying` 状态：删除半成品副本，状态改为 Aborted（源完好）。
   - `CopiedVerified`、`DeletingSource`、`Restoring` 状态：改为 NeedsAttention，由界面提供“继续（逐项复核）”或“放弃（删除副本，保留源）”。
6. 还原：原位置已存在同名文件时视为冲突，跳过该条目；需要的父目录用 `create_dir_all` 创建。复制回原位置并校验哈希后，再通过 guard 删除副本。
7. 彻底删除：以批次目录为锚点，通过 guard 删除整个批次目录树（目录后序删除）。
8. 执行器分派：`Recovery::Quarantine` 的规则交给隔离引擎处理（T12 才会有这类规则）。
9. 命令：`quarantine_volumes()`、`quarantine_set_volume(volumeRoot)`（只接受 `candidate_volumes` 返回列表中的值）、`quarantine_batches()`、`quarantine_restore(batchId)`、`quarantine_purge(batchId)`、`quarantine_resolve(batchId, action)`、`quarantine_overdue()`。
10. 隔离区页：
    - 设置卡：选择卷，显示剩余空间。
    - 批次列表：时间、来源规则、条目数、大小、状态、存放天数；操作有“还原”“彻底删除”（需确认）“处理异常”。
    - 应用启动时，如果有超过 7 天的批次，显示横幅提示，由用户手动处理。

## 不要做
不创建后台任务；不自动删除到期批次；没有可选卷时，不退回到 C 盘隔离。

## 必须编写的测试（`tests/quarantine.rs`；用 `QuarantineRoot::for_test(tempdir)` 允许同卷；剩余空间通过注入的 provider 提供）
1. 隔离后再还原：内容哈希和 mtime 与原来一致，副本被清除，批次状态为 Restored。
2. 复制完成后、删除源之前修改源文件：该条目的源保留，批次为部分完成，副本仍在。
3. 崩溃恢复：注入在第 N 个文件后中断，使批次停在 Copying 状态；`recover_pending` 之后源完好，半成品副本被删除。
4. 空间不足：整批拒绝，目标目录中没有任何写入。
