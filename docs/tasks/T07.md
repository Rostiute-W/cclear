# T07 冻结清单、日志与执行器

- 里程碑：M2
- 依赖：T06

> 执行者先阅读仓库根目录的 `AGENTS.md`。本文件之外的需求一律不做。

## 目标
实现“预览清单就是执行的唯一输入”：构建冻结清单 → 执行时逐项复核 → 每一步写入日志。

## 实现要点
1. `plan/`：
```rust
pub struct FrozenItem { pub item_id: u32, pub rule_id: &'static str, pub anchor_index: u16, pub rel: Vec<OsString>, pub is_dir: bool,
  pub identity: FileIdentity, pub size: u64, pub allocated: u64, pub mtime: u64 }
pub struct PlanRule { pub rule_id: &'static str, pub recovery: Recovery, pub anchors: Vec<PathBuf>, pub items: Range<u32>, pub total: SizeInfo, pub skipped_at_build: Vec<(PathBuf, String)> }
pub struct FrozenPlan { pub plan_id: Uuid, pub created_at: OffsetDateTime, pub rules: Vec<PlanRule>, pub items: Vec<FrozenItem> }
pub fn build_plan(rules: &[&Rule], roots: &RootMap, forbidden: &Forbidden, procs: &[ProcInfo], now: SystemTime) -> Result<FrozenPlan>;
```
   - 只接受 recovery 为 `Regenerable` 或 `IrreversibleFile`、Target 为 `Paths` 或 `ChromiumProfiles` 的规则。调用方（app 层）负责只传入 executable 的规则；测试可以直接构造 Rule。
   - 构建过程：用 `guard::open_anchor` 打开锚点，再用 `guard::list_dir` 递归遍历。遇到 reparse 条目时跳过，并在 `skipped_at_build` 中记录“链接，已跳过”；组件名属于禁区的直接跳过；文件路径等于任一运行中进程映像路径的也跳过（“正在运行的程序文件”）。
   - 按选择器选文件。对于 `AllContents` 和 `ChildDirs`，把目录按后序加入清单（锚点本身永不加入）。
2. `journal/`：
   - `trait JournalSink { fn append(&mut self, r: &Record) -> io::Result<()>; }`
   - `FileJournal` 写入 `<LocalAppData>\CClear\journal\YYYY-MM-DD.jsonl`：每条记录 `write_all` + `flush`，每 256 条以及计划结束时调用一次 `sync_data`。
   - `Record` 为 serde tag 枚举，先包含 `PlanStarted`、`ItemDone`、`ItemSkipped`、`RuleSkipped`、`PlanFinished`（含 free_before、free_after），后续任务会继续添加变体。
   - `read_summaries(days) -> Vec<PlanSummary>`：解析失败的行跳过并计数。
3. `exec/executor.rs`：
   - `execute(plan, selected_rule_ids, procs_now: &dyn Fn() -> Vec<ProcInfo>, journal, cancel, progress) -> ExecReport`
   - 每条规则开始前重新获取进程列表，相关进程在运行就跳过整条规则（写 `RuleSkipped`）。
   - 每个条目：`open_rel(Delete)` + `delete(Expect)`。错误映射为中文原因：已变化、已不存在、被占用、无权限、只读、目录内有未计划的新文件已保留、路径中出现链接。
   - 每处理完一个条目就写日志；**日志写入失败时立即中止**，`aborted = Some("日志写入失败，已停止")`。
   - 每个条目检查一次 `cancel`。
   - 记录执行前后锚点所在卷的剩余空间。
   - `ExecReport` 按规则统计删除的文件数、目录数、释放的 allocated、跳过数；跳过明细最多保留 200 条。
4. Tauri 命令（AppState 增加 `PlanStore: Mutex<HashMap<Uuid, FrozenPlan>>`）：
   - `plan_build(ruleIds) -> PlanSummaryDto`：只接受 executable 的规则，否则报错
   - `plan_items(planId, ruleId, offset, limit)`
   - `plan_execute(planId, ruleIds, onProgress: Channel)`
   - `plan_cancel()`
   - `history_list(days)`
   前端只需在 `api.ts` 中封装，界面在 T08 实现。

## 不要做
不开放任何 Phase（ENABLED_PHASES 仍为空），不做 UI，不实现隔离和命令类规则。

## 必须编写的测试（`tests/executor.rs`，构造指向 tempdir 的 Rule 和 RootMap）
1. 正常执行：清单内的文件全部删除，变空的子目录被删除，锚点本身和锚点外的哨兵都保留。
2. 构建清单后修改某个文件（mtime 变化），该文件被跳过且仍在；构建后新增文件的目录被保留（原因为“目录内有未计划的新文件已保留”）。
3. 日志失败：注入一个第 2 次 append 就失败的 sink，执行在此处中止，剩余文件仍在。
4. 锚点内有 junction 指向外部目录：清单跳过它，执行后外部目录的内容不变。
