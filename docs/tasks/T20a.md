## 目标
用户可以在设置里填写 AI 服务地址、模型名和 API Key；在清理页对拿不准的规则点“问 AI”，后端把该规则的说明、占用和样例路径脱敏后发给用户配置的 OpenAI 兼容接口，返回 AI 对“这是什么、能不能清理”的评估。AI 的回答只展示，不影响任何执行。本任务只做后端和 `api.ts`/`types.ts`，界面留给 T20b。

## 实现要点

### A. Win32 封装（`crates/cclear-core/src/win/`）
1. `win/http.rs`：`pub fn post_json(url: &str, headers: &[(&str, &str)], body: &[u8], limit: usize) -> io::Result<HttpResponse>`，`HttpResponse { status: u32, body: Vec<u8> }`。用 WinHTTP 实现：`WinHttpOpen`（UA `CClear/<版本>`，`WINHTTP_ACCESS_TYPE_AUTOMATIC_PROXY`）→ `WinHttpCrackUrl` → `WinHttpConnect` → `WinHttpOpenRequest("POST", ..., https 时 WINHTTP_FLAG_SECURE)` → `WinHttpSetTimeouts`（解析 15 秒、连接 15 秒、发送 30 秒、接收 120 秒）→ 设置 `WINHTTP_OPTION_REDIRECT_POLICY` 为 `WINHTTP_OPTION_REDIRECT_POLICY_NEVER`（重定向会把 Authorization 头带到别的主机）→ `WinHttpSendRequest` → `WinHttpReceiveResponse` → 读状态码 → `WinHttpReadData` 循环读取，累计超过 `limit` 字节就返回错误。所有句柄用 RAII 关闭。每个 `unsafe` 块一行 `// SAFETY:`。
2. `win/dpapi.rs`：`pub fn protect(data: &[u8]) -> io::Result<Vec<u8>>` 和 `pub fn unprotect(data: &[u8]) -> io::Result<Vec<u8>>`，用 `CryptProtectData`/`CryptUnprotectData`（当前用户范围，`CRYPTPROTECT_UI_FORBIDDEN`），输出缓冲区用 `LocalFree` 释放。
3. `crates/cclear-core/Cargo.toml` 的 `windows` features 加 `Win32_Networking_WinHttp`、`Win32_Security_Cryptography`（如编译需要再加 `Win32_System_Memory`）。不新增任何 crate。

### B. 设置（`crates/cclear-core/src/quarantine/settings.rs`）
4. 设置文件全项目只有这一份。在现有 `Settings` 结构里加 `ai_base_url: Option<String>`、`ai_model: Option<String>`、`ai_api_key: Option<String>`（都 `#[serde(default, skip_serializing_if = "Option::is_none")]`）。**必须加在同一个结构里**：`save_quarantine_root` 是整份读出再整份写回，放在另一个结构里会互相把对方的字段写丢。
5. 新增 `pub fn load_ai_settings() -> io::Result<AiSettings>` 和 `pub fn save_ai_settings(base_url: &str, model: &str, api_key: KeyUpdate) -> io::Result<()>`。`KeyUpdate` 为 `Keep` / `Clear` / `Set(String)`。`Set` 时先 `dpapi::protect`，存成 `"dpapi:" + 小写十六进制`；读出时只接受这个前缀，其他内容当作没有 Key。保存同样是读出整份 → 改 AI 字段 → 写回，隔离区字段原样保留。
6. `AiSettings` 不实现 `Debug` 输出明文 Key；解密后的 Key 只在发请求的函数里短暂存在，不写日志、不进错误信息、不返回前端。

### C. AI 逻辑（新目录 `crates/cclear-core/src/ai/mod.rs`）
7. `pub fn endpoint_url(base: &str) -> Result<String, AiError>`：去掉首尾空白和末尾 `/`；只接受 `https://`，或者主机是 `localhost`、`127.0.0.1`、`[::1]` 的 `http://`（本地 Ollama 之类）；地址里带 `@`（用户信息）、`?`、`#` 一律拒绝；以 `/chat/completions` 结尾的原样使用，否则在末尾加 `/chat/completions`。保存设置时也调用它校验。
8. `pub fn redact(text: &str, profile: &Path) -> String`：先把所有不区分大小写出现的用户目录（如 `C:\Users\ZhuanZ`，`\` 和 `/` 两种写法）替换成 `%USERPROFILE%`；再把以 `\`、`/`、开头、结尾、空白或引号为边界、等于用户目录最后一级名字（用户名）的片段替换成 `<用户名>`。大小写比较用 `win::equals_ignore_case`，不用 `to_lowercase`。`profile` 由调用方传入（生产代码用 `known_folder(KnownFolder::Profile)`），测试注入临时值。
9. `pub fn rule_messages(ctx: &RuleContext, profile: &Path) -> Vec<ChatMessage>`：
   - system 消息（固定中文）：你是 Windows C 盘清理顾问；根据给出的信息判断这些文件的用途和清理影响；不确定就直说“无法判断”，不要编造；按下面四段回答：【这是什么】【清理后会怎样】【建议】（只能是“建议清理”“可以清理，但要注意……”“不建议清理”“无法判断”之一）【理由】；总长度不超过 400 字。
   - user 消息：规则名称、分级（安全/谨慎/残留/仅分析 等中文名）、恢复方式中文名、说明、注意事项、需关闭的进程、当前状态、占用大小（二进制单位 GB/MB）、文件数、锚点（最多 5 条）、样例路径（最多 10 条）、判定依据和备注（各最多 10 条）、用户补充的问题（可选，截断到 500 字）。所有文本都经过 `redact`。整个 user 消息超过 8000 字符时从样例路径开始截断。
10. `pub fn ask(endpoint: &str, model: &str, api_key: &str, messages: &[ChatMessage]) -> Result<String, AiError>`：请求体 `{"model", "messages", "temperature": 0.2, "stream": false}`；头 `Content-Type: application/json`，Key 非空时加 `Authorization: Bearer <key>`；响应上限 2 MiB；取 `choices[0].message.content`。状态码不是 2xx 时，错误信息是“AI 服务返回错误（状态码）：”加上响应 JSON 里 `error.message` 的前 300 字（取不到就只写状态码）。所有错误信息都不能包含 Key。
11. `AiError` 用 `thiserror`，放在 `error.rs` 或 `ai/mod.rs`（与现有模块风格一致），中文信息：地址不合法、没有配置 AI、网络失败、服务返回错误、响应格式不对、响应过大。

### D. Tauri 命令（`src-tauri/src/commands/ai.rs`，按 AGENTS.md 规则 8 四处同步）
12. `ai_settings_get() -> AiSettingsDto { baseUrl, model, hasKey }`：不返回 Key。
13. `ai_settings_save(baseUrl: String, model: String, apiKey: Option<String>) -> AiSettingsDto`：`apiKey` 为 `None` 保留原 Key，`Some("")` 清除，其他值加密保存；Key 超过 4096 字符拒绝；`baseUrl` 用 `endpoint_url` 校验，模型名不能为空。
14. `ai_ask_rule(ruleId: String, question: Option<String>) -> AiAnswerDto { answer, model, sent }`：在内置规则目录里按 ID 找规则（找不到报错）；用 `RootMap::system()`、`running_processes()`、`resolve::evaluate` 重新评估这一条规则拿到最新的锚点、大小、样例和依据；`known_folder(KnownFolder::Profile)` 作为脱敏依据；读设置、解密 Key、调用 `ask`。`sent` 是实际发出的 user 消息文本（已脱敏），界面用来让用户看到发了什么。整个过程放在 `spawn_blocking` 里；只读，不拿执行锁。
15. `src/types.ts` 加 `AiSettings`、`AiAnswer`；`src/api.ts` 加 `aiSettingsGet`、`aiSettingsSave`、`aiAskRule`。
