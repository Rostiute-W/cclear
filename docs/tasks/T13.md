# T13 工具缓存目录的官方配置迁移

- 里程碑：M4
- 依赖：T12

> 执行者先阅读仓库根目录的 `AGENTS.md`。本文件之外的需求一律不做。

## 目标
把 uv、pip、npm、NuGet、Gradle 的缓存位置改到其他盘，按工具官方支持的方式修改配置，并先验证新位置已经生效，再清理旧目录。

## 实现要点
1. 配置方式：

| 工具 | 方式 | 验证命令 |
|---|---|---|
| uv | 用户环境变量 `UV_CACHE_DIR` | `uv cache dir` |
| pip | 用户环境变量 `PIP_CACHE_DIR` | `pip cache dir` |
| npm | `npm config set cache <path> --location=user` | `npm config get cache` |
| NuGet | 用户环境变量 `NUGET_PACKAGES`（global-packages）和 `NUGET_HTTP_CACHE_PATH` | `dotnet nuget locals all --list` |
| Gradle | 用户环境变量 `GRADLE_USER_HOME`（会迁移整个 .gradle，包括配置，界面要明确提示） | 检查目录 |

   - 写用户环境变量：`win/registry.rs` 写 `HKCU\Environment`（REG_SZ），然后广播 `SendMessageTimeoutW(HWND_BROADCAST, WM_SETTINGCHANGE, 0, "Environment")`。
   - 所有命令都通过 `exec::command::run` 执行。
2. 流程（状态机持久化在 `<LocalAppData>\CClear\migrations.json`，并写日志 `Record::Migration*`）：
   1. 检查：当前生效路径、配置来源（环境变量 / npmrc / 默认值）、大小、是否在 C 盘
   2. 用户选择目标卷（固定 NTFS、非 C 盘）→ 目标路径 `<X>:\CClearData\<tool>`；选择模式：“迁移旧缓存”或“允许重建”
   3. 预检：相关进程（node、uv、python/pip、dotnet、java）在运行时给出警告，需要用户确认
   4. 如果选择“迁移”，用 `quarantine::copy_tree_verified` 复制并校验
   5. 记录旧配置值，然后写入新配置
   6. 验证：构造新的环境块（当前环境 + 新变量），启动新进程运行验证命令，生效路径必须等于目标（按目录 identity 比较）。不相等时恢复旧配置，并报告失败。
   7. 提示“请重启 IDE 和终端”
   8. 由用户单独确认后清理旧目录：以旧目录为锚点构造一条临时规则（Recovery 为 IrreversibleFile），走 `plan_build → PlanPreview → plan_execute`
   9. 撤销：恢复旧配置值（旧目录已经清理的情况下，缓存会自动重建）
3. `CARGO_HOME` 和 `RUSTUP_HOME`：只显示说明文字，不提供自动迁移。
4. 命令：`migrations_list()`、`migration_inspect(tool)`、`migration_start(tool, volumeRoot, mode)`、`migration_cleanup_old(tool) -> planId`、`migration_revert(tool)`。参数里的 tool 和 mode 是 enum 字符串，volumeRoot 必须来自候选卷列表。
5. 迁移页的“工具缓存目录”区：表格列出各工具的当前路径、大小、是否在 C 盘、状态，以及对应操作。

## 不要做
不修改系统级环境变量，不修改项目级配置，不做 junction（T16）。不写测试（涉及注册表和真实工具，靠审查和手工验收）。
