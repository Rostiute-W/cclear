# T05a 检查点 A 修复：规则路径、禁区与只读页面问题

- 里程碑：M1（检查点 A 返工）
- 依赖：T05
- **完成并合并后暂停，等用户通知 Droid 复审，复审通过后才开始 T06**

> 执行者先阅读仓库根目录的 `AGENTS.md`。本文件之外的需求一律不做。下文的路径都已经由 Droid 在用户机器上只读核实过，照写即可，不需要再去读取真实用户目录。

## 目标
修复检查点 A 审查发现的问题：规则路径写错导致候选永远是“未找到”、禁区判断漏掉子目录、规则范围重叠、Profile 名可越界，以及清理页和环境状态卡的几处误导显示。全程仍然只读，不实现任何执行逻辑。

## 实现要点

### A. 禁区（`rules/forbidden.rs`）
1. 具体路径禁区改为“路径中含有这段连续组件”（任意位置，不区分大小写），覆盖整棵子树。现在的 `ends_with` 只匹配末尾，`...\QQ\auth\xxx`、`...\office6\backup\某文件` 都漏判。
2. 按 plan-final §4，把 `auth`、`security` 加入 `forbidden_names()`（任意位置的组件名都算禁区）。`QQ\auth`、`QQ\security` 两条具体路径随之可以删除。
3. 禁区补充 `<LocalAppData>\com.zhuanz.cclear`（Tauri/WebView2 数据目录，标识符取自 `tauri.conf.json`），原因写“CClear 自身数据禁止”。

### B. 规则路径修正（`rules/catalog.rs`）
4. `app-qq-cache` 拆成两条（都保持 caution / regenerable / M3b，进程都是 `QQ.exe`、`QQEX.exe`）：
   - `app-qq-cache`：root `RoamingAppData`，rels `QQ\Cache`、`QQ\Code Cache`、`QQ\GPUCache`，layout_markers `["QQ\Partitions"]`。
   - `app-qqex-cache`：root `RoamingAppData`，rels `QQEX\Cache`、`QQEX\Code Cache`、`QQEX\GPUCache`、`QQEX\users\*\Cache`、`QQEX\users\*\Code Cache`、`QQEX\users\*\GPUCache`，layout_markers `["QQEX\users"]`。
   - 选择器为 AllContents，不要用 `Documents\Tencent Files`。
5. `app-wechat-log`：root `RoamingAppData`，rels `Tencent\xwechat\log`。
6. `app-qq-log`：rels 改为 `Tencent Files\*\nt_qq\nt_data\log`（root 仍为 Documents）。
7. `user-temp` 不能包含 `DockerDesktopUpdates`（它属于 M4 的 leftover/quarantine 规则）。给 `Selector` 增加字段 `exclude_child_dirs: &'static [&'static str]`，含义是锚点下一层按名称（支持 `*`/`?`、不区分大小写）排除的子目录，其他规则都填 `&[]`。`user-temp` 填 `["DockerDesktopUpdates"]`。
8. 新增 `CommandId::UvCacheClean` 和规则 `command-uv-cache-clean`（caution / irreversible_command / M3b，warning “执行前需二次确认”）。删除 `command-npm-cache` 上的 “执行前需二次确认” 警告。
9. manual 规则修正（仍然一律 `Phase::Analysis` + `Recovery::None`）：
   - `manual-wps-addons-pool`：RoamingAppData `kingsoft\wps\addons\pool`
   - `manual-wps-download-update`：RoamingAppData `kingsoft\wps\download`、`kingsoft\office6\update`
   - `manual-dingtalk-cache`：RoamingAppData `DingTalk\Temp`、`DingTalk\xcdn`、`DingTalk\*_v3\resource_cache`
   - `manual-hibit-backup`：RoamingAppData `HiBit Uninstaller\Uninstaller\Backup`
   - `manual-media-apps`：RoamingAppData `bilibili`、`youku-app`、`Tencent\WeMeet`、`Tencent\QQMusic`
   - `manual-package-cache` 拆成两条：LocalAppData `Package Cache`；ProgramData `Package Cache`（新 id `manual-programdata-package-cache`）
   - `manual-powertoys`：LocalAppData `PowerToys`（程序本体）
   - `manual-user-dirs` 拆成三条：`KnownRoot::Documents` 根目录本身、`KnownRoot::Downloads` 根目录本身、Profile `DeskBox`；去掉 `Desktop`
   - `manual-wsl-vhdx`：名称改为“未关联虚拟磁盘（WSL）”，root LocalAppData，rels `wsl\*`，`TopFiles(["*.vhdx"])`。不要再用 `Packages\*\LocalState`（那是禁区，且是已注册发行版的位置）
   - rels 为空字符串或 `.` 表示根目录本身时，`resolve_anchors` 需要能正确处理

### C. 候选解析（`rules/resolve.rs`）
10. Chromium Profile 名只接受单个普通路径组件：不能为空，不能是 `.` 或 `..`，不能含 `\`、`/`、`:`。不合格的键直接忽略。
11. 解析锚点时不跟随 reparse point：从 RootMap 的根往下，规则展开出来的每一级目录（包括 Chromium 的 `User Data`、Profile 和叶子目录）只要是 reparse point，就丢弃这个锚点。不要再用会跟随链接的 `Path::is_dir()` 做这个判断。`layout_markers` 同理。
12. 统计（`measure`）和占用检查（`lock_files`）对文件的取舍必须一致：都跳过 reparse 文件（与扫描器 `classify_file` 的 Skip 规则相同），都按“卷序列号 + 文件 ID”去重，都执行第 7 条的 `exclude_child_dirs`，并且都不进入名称命中 `forbidden_names()` 的子目录。最好让两者共用一套枚举。
13. 候选没有任何文件时（包括命令、适配器、特殊操作这类没有锚点的规则），`check_locks` 返回 `complete = false`，error 为“没有可检查的文件”。

### D. 环境状态卡（`envstate.rs`）
14. 判断“是否在 C 盘”时，同时支持 `X:\` 和 `\\?\X:\` 两种前缀，按盘符比较。现在 `\\?\C:\...` 会被误判为“已在其他盘”。
15. 页面文件：先读 `PagingFiles`；其中有 `?:` 开头的项（系统自动管理）时，改读同一键下的 `ExistingPageFiles`（`REG_MULTI_SZ`，形如 `\??\G:\pagefile.sys`，去掉 `\??\` 前缀）来得到实际位置。两者都读不到时仍显示“未知”。
16. 新增 `unregistered_vhdx: Option<Vec<Location>>`：列出 `<LocalAppData>\wsl\*\` 下的 `*.vhdx`，去掉所在目录与某个已注册发行版 `BasePath` 相同（规范化前缀后，不区分大小写比较）的项。总览页在 WSL 分组下显示为“未关联虚拟磁盘”，并带文件大小。只读，不做任何处理。

### E. Tauri 命令与前端
17. `open_candidate_in_explorer` 改为 async + `spawn_blocking`（与 `candidate_locks` 相同），避免在主线程重新统计磁盘。
18. 清理页徽标：`status == "ready"` 且 `executable == false` 时显示“将在 {phase} 开放”，不能显示“可执行”。直接使用 `RuleInfo` 已有的 `phase` 字段，不要新增命令。
19. 规则没有锚点时（状态为 notPresent、phaseLocked，或者 anchors 为空），“检查占用”和“打开位置”两个按钮禁用。
20. `types.ts` 同步第 16 条新增的字段。
21. 总览页：`onedrive` 为 null（没有配置）时显示“没有配置 OneDrive”，不要显示“未知”。
