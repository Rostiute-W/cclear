# T09 开放安全与谨慎层的文件类规则以及 C 盘回收站

- 里程碑：M3
- 依赖：T08

> 执行者先阅读仓库根目录的 `AGENTS.md`。本文件之外的需求一律不做。

## 目标
第一次开放真实清理：safe 和 caution 层中 Target 为 `Paths` 或 `ChromiumProfiles` 的规则，以及“清空 C 盘回收站”。

## 实现要点
1. `ENABLED_PHASES = [M3a, M3b]`。命令类规则（`Target::Command`）的状态仍是 PhaseLocked，留给 T10。
2. 清理页：
   - 启用 executable 候选的勾选框，默认勾选状态按 `default_selected`。
   - 安全组有“一键清理安全项”按钮：选中所有 Ready 的 safe 候选 → `plan_build` → `PlanPreview` → 执行 → 自动重新评估。
   - 谨慎组有“清理选中项”按钮，流程相同。
3. `special/recycle_bin.rs`：
   - `query_c() -> (items: i64, bytes: i64)`：调用 `SHQueryRecycleBinW("C:\\")`
   - `empty_c()`：调用 `SHEmptyRecycleBinW(None, "C:\\", SHERB_NOCONFIRMATION | SHERB_NOSOUND)`
   - 命令 `recycle_bin_query()` 和 `recycle_bin_empty(expectedItems, expectedBytes)`：执行前重新查询，条目数或大小与预期不一致时返回错误“回收站内容已变化，请重新确认”。
   - 写日志 `Record::SpecialAction`。
4. 回收站在谨慎组中单独成行，有独立的确认对话框，文案：“将清空执行时 C 盘回收站的全部内容（当前 N 项，X GB），不可恢复”。
5. 执行器在 build 和执行时会检查相关进程。界面上，进程在运行的候选显示“请先退出 xxx”，并且不可勾选。
6. 检查点 B 复审追加（先做这一条，再开放执行）：
   - **护栏能打开“只缺遍历权限”的目录**：真实机器上 `%LOCALAPPDATA%\Temp\nsg75A7.tmp`（安装程序留下的目录）的 ACL 只有 `Everyone:(OI)(CI)(D,Rc,RD,DC)`。`guard` 打开目录时申请了 `FILE_TRAVERSE | FILE_READ_ATTRIBUTES`，因此返回“没有访问权限”；`win::dirinfo::open_dir` 只申请 `FILE_LIST_DIRECTORY | SYNCHRONIZE`，可以读到。结果是 user-temp 的评估为 588 个文件，清单只有 586 个，违反 T07 第 5 条“同一批文件”。修法：把 `guard/path.rs` 中目录角色（`Role::Directory` 和 `open_volume_root`）的访问权限收窄到实际需要的最小集合（相对打开不需要父句柄有遍历权限）。身份、reparse 和禁区检查一项都不能少。如果某项检查确实需要额外权限、做不到，就改成方案 B：让 `resolve` 枚举目录时使用和护栏完全相同的权限，两边一起排除这类目录。最终说明里写明采用了哪种方案以及原因。
   - **清单构建不能静默丢目录**：`plan::build_plan` 中 `guard::list_dir` 失败时，把该目录记进 `skipped_at_build`，原因写“无法读取目录，已跳过：<中文错误>”。
   - **全部规则评估跨规则并行**：`rules_evaluate` 目前逐条规则串行评估，冷启动实测 4.35 秒，热缓存 2.81 秒，目标是冷启动也在 3 秒以内。在 `rules/resolve.rs` 增加 `pub fn evaluate_all(roots, procs, now) -> Vec<Candidate>`，用 rayon 跨规则并行，输出顺序与 `catalog()` 相同。`rules_evaluate` 和其他需要评估全部规则的地方都改用它。不写测试，由 Droid 在检查点 C 用真实数据复测。
   - **取消的执行在历史里要标出来**：取消后现在仍写 `PlanFinished`，历史页显示“已正常结束”。给 `Record::PlanFinished` 增加 `cancelled: bool`（`#[serde(default)]`，旧日志行按 false 读），`PlanSummary`/`PlanDetail` 及其 DTO 带上这个字段。历史列表和详情把取消的执行显示为“已取消”。
