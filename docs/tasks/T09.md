# T09 开放安全与谨慎层的文件类规则以及 C 盘回收站

- 里程碑：M3
- 依赖：T08

> 执行者先阅读仓库根目录的 `AGENTS.md`。本文件之外的需求一律不做。

## 目标
第一次开放真实清理：safe 和 caution 层中 Target 为 `Paths` 或 `ChromiumProfiles` 的规则，以及“清空 C 盘回收站”。

## 实现要点
1. `ENABLED_PHASES = [M3a, M3b]`。命令类规则（`Target::Command`）的状态仍是 PhaseLocked，留给 T10。
2. 清理页：
   - 启用 executable 候选的勾选框，默认勾选状态按 `default_selected`。
   - 安全组有“一键清理安全项”按钮：选中所有 Ready 的 safe 候选 → `plan_build` → `PlanPreview` → 执行 → 自动重新评估。
   - 谨慎组有“清理选中项”按钮，流程相同。
3. `special/recycle_bin.rs`：
   - `query_c() -> (items: i64, bytes: i64)`：调用 `SHQueryRecycleBinW("C:\\")`
   - `empty_c()`：调用 `SHEmptyRecycleBinW(None, "C:\\", SHERB_NOCONFIRMATION | SHERB_NOSOUND)`
   - 命令 `recycle_bin_query()` 和 `recycle_bin_empty(expectedItems, expectedBytes)`：执行前重新查询，条目数或大小与预期不一致时返回错误“回收站内容已变化，请重新确认”。
   - 写日志 `Record::SpecialAction`。
4. 回收站在谨慎组中单独成行，有独立的确认对话框，文案：“将清空执行时 C 盘回收站的全部内容（当前 N 项，X GB），不可恢复”。
5. 执行器在 build 和执行时会检查相关进程。界面上，进程在运行的候选显示“请先退出 xxx”，并且不可勾选。

## 不要做
不开放命令类、leftover、提权类规则。不写测试（判定逻辑已在 T04、T07 中测试过）。

## 必须编写的测试
无。
