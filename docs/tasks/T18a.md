## 实现要点

### A. 启动恢复要等用户确认备份（P1）
现状：迁移记录主文件 JSON 损坏、从 `migrations.json.bak` 读出时（`migrate/mod.rs:1523-1534` 置 `from_backup`），用户操作入口都有 `refuse_without_backup`，但启动恢复没有：`src-tauri/src/commands/migrate.rs:499-500` 无条件调用 `recover_directories` 和 `recover_tools`，`junction.rs` 的 `recover_pending`（约 1055-1146 行）和 `migrate/mod.rs` 的 `recover_tools`（约 693-723 行）都不检查。备份比主文件旧一个版本，按它恢复会删除目标副本（`junction.rs:1086`）或把配置改回旧值，而且之后保存被拒绝，每次启动都会重复。
1. 两个恢复入口开头检查 `from_backup`，为真时什么都不做，返回一条恢复说明“迁移记录是从备份读出来的，请先在迁移页确认使用备份，确认后会再做一次启动恢复”。
2. `migration_confirm_backup` 命令在确认成功之后，持有执行锁调用一次与启动时相同的恢复流程（复用 `recover_on_startup` 的逻辑），结果写进恢复说明。

### B. 还原时按名字清理临时文件（P2）
3. `quarantine/mod.rs:1522`、`1199` 每个条目都调用 `remove_stale_restore_temp` / 类似逻辑，内部 `guard::list_dir` 枚举整个父目录（`1598`、`1613-1625`）。临时文件名是确定的（`<名>.cclear-restore-<批次前 8 位>`），改为直接 `open_rel` 这个名字，存在且是普通文件就通过 guard 删除，不再枚举目录。

### C. 迁回改名失败且父目录打不开时保留临时目录（P2）
4. `junction.rs:973-983` 这个分支不要调用会删除临时目录的 `abort_return`：保留临时目录，状态记为 `NeedsAttention`，说明里写出临时目录的完整路径（与函数文档 951-954 行一致）。

### D. 界面细节（P2）
5. 隔离区剩余空间：`src-tauri/src/commands/quarantine.rs:303-306` 对还不存在的隔离根目录查询剩余空间会得到 0（本机实测界面显示“剩余 0 B”）。改为查询该根目录所在卷的根（如 `D:\`）。
6. 总览环境状态卡：恢复“页面文件”和“OneDrive”的小标题或标签（后端这两类条目的 `name` 为空，`crates/cclear-core/src/envstate.rs:41`），让路径前有说明。
7. `App.tsx:90`：`appInfo` 失败时仍显示“版本 —”和“普通权限”，与原注释一致。
8. `Clean.tsx:842-843`：回收站“N 项”徽标改用中性色，不用 safe 绿色。
9. 清理页规则表在 1100 宽窗口下名称列被挤成两行（如“Edge 浏览器缓存”）：调整列宽，名称列不换行或给足最小宽度，说明列可以换行。
10. 加载状态：隔离区批次（`Quarantine.tsx:191`）、历史（`History.tsx:77`）、总览卷信息（`Overview.tsx:110`）、空间分析扫描结果，在首次数据返回之前显示“加载中”，不要先闪一下空状态。只加一个 loading 标志，不改调用逻辑。
