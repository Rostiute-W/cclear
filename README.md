# CClear

CClear 是一个个人自用的 Windows 11 桌面工具，用来清理 C 盘、分析空间占用，并把缓存目录和纯数据目录搬到大容量磁盘。

设计前提只有一条：**先分析，再动手**。每条规则必须在本机有验证证据才有执行资格；证据不足的项保持只读，只展示大小和操作指引。任何失败都只会导致“跳过并报告”，不会扩大删除范围，也不会提升权限去兜底。

默认按当前用户安装、以普通权限运行；除在用户主动点击“问 AI”时向你自己在设置页填写的地址发送一次咨询请求外，不联网、不做遥测、不自动更新，也没有常驻进程、托盘或定时任务。

## 功能概览

界面有六个页面：

- **总览**：C 盘占用环形图、其他固定盘的条形列表、扫描入口，以及环境状态卡。
  - 可以扫描 C 盘或用户目录，扫描中显示目录数、文件数、已统计大小、耗时，可随时取消。
  - 有拒绝访问的目录时明确提示“N 个目录无权读取（普通权限扫描不完整）”。
  - 环境状态卡列出休眠、页面文件、WSL 发行版、桌面/文档/下载等 Known Folder 的实际位置，以及 OneDrive 路径，用“已在其他盘 / 在 C 盘”的方式展示，也可能显示“未知”。
- **清理**：按等级分组的规则候选，逐项显示占盘大小、状态、说明和样例路径，可以检查占用、打开位置、查看判定证据。
  - 安全层可一键清理，谨慎层逐项勾选后清理，残留层的条目一律先进隔离区。
  - 命令类规则在“不可撤销命令”分组里单独运行，系统维护项在“系统维护（需要管理员）”分组里单独执行。
  - C 盘回收站是独立操作，单独成行。
- **空间分析**：目录列表、图形（treemap）和 Top 文件三个页签，共用面包屑逐级进入，可以打开位置，也可以把某个目录送去迁移。
- **隔离区**：选择保存卷，查看隔离批次，按批次还原或彻底删除，处理需要人工决定的异常批次。
- **迁移**：工具缓存目录的官方配置迁移，以及纯数据目录的 junction 迁移与迁回。
- **历史**：清理记录（时间、规则、释放空间、跳过数），可以展开查看逐条详情和跳过原因，被取消的执行会标成“已取消”。
- **AI 咨询**：可在「设置」页配置 OpenAI 兼容接口（需使用 HTTPS，本机地址可用 HTTP），API Key 以 Windows DPAPI 加密保存在本地。在「清理」页任意规则旁点击“问 AI”时发送一次只读请求，发送前自动脱敏本机路径与用户名；回答仅供参考，不影响任何清理、隔离或迁移行为。

## 分级与恢复方式

每条规则同时带一个等级和一个恢复方式。

等级决定界面怎么用：

| 等级 | 含义 | 界面行为 |
|---|---|---|
| safe | 可再生，且已有本机验证记录 | 一键清理（执行前先在预览里展示汇总，可展开） |
| caution | 可再生但有代价，或者是诊断数据 | 逐项勾选后清理 |
| leftover | 有产品适配器证据的多版本残留 | 逐项勾选，默认进入隔离区 |
| manual | 用户数据、程序本体、证据不足的项 | 只分析和引导（打开位置 / 官方卸载 / 迁移 / 送回收站） |
| forbidden | 硬性禁区 | 不可选中，只列出名称和原因 |

恢复方式说明清理之后还能不能退回：

| 恢复方式 | 含义 |
|---|---|
| 可再生 | 直接删除，应用重新生成即可 |
| 永久删除 | 删除不可再生的文件，需要逐项确认 |
| 隔离 | 先复制到隔离区并校验，再删源，随时可以还原 |
| 不可撤销命令 | 调用工具自己的官方命令，标明作用范围和不可撤销，无法逐文件预览 |

## 安全设计要点

- **冻结清单**：预览时生成的清单是执行的唯一输入，记录路径、卷 + 文件 ID、大小、时间和规则版本。执行时逐项复核，有变化的条目跳过并提示重新扫描；目录里出现清单之外的新文件时，该目录整体保留，不会连带删除。
- **路径护栏（guard）**：全项目唯一允许删除、改名、创建 junction 的地方。它从卷根开始逐组件相对打开目录，任一组件是链接或落在禁区就拒绝；删除前在同一个句柄上复核文件身份、大小和修改时间，再按句柄删除，不对字符串路径调用删除。也正因为如此，预览之后路径被替换、同名文件被换掉、用 8.3 短名绕过禁区这类竞态都拦得住。
- **隔离区**：位于另一块固定 NTFS 盘（排除系统盘、源盘和 OneDrive 所在盘），按“预检 → 复制 → 逐文件哈希与元数据校验 → 确认源未变化 → 删源”推进，状态机写在批次清单里。进程中途被结束时，源文件还没删，下次启动会把半成品副本清掉；停在需要人工确认的状态时，由界面提供“处理异常：继续 / 放弃”。
- **迁回**：junction 迁移把纯数据目录整棵复制到目标盘并校验（空目录也跟着保留），源目录改名成备份、原位置建 junction，经 junction 读回文件比对哈希后才交给用户实测。迁回以目标盘中的最新数据为准：先按来源盘（不是 C 盘）的剩余空间判断够不够，再把数据复制到来源盘上的临时目录 `<目录名>.cclear-return-<id>`，复制前后各核对一次目标没有被进程占用、内容没有变化，然后才移除 junction 并改名回原名。复制失败或复核不通过会删掉临时目录、状态回到迁回之前；链接已经删掉而改名失败时先尝试把 junction 建回去，建不回来就保留临时目录并在说明里写出它的完整路径。中间状态写在迁移记录里，进程被结束后下次启动能把迁回收尾。
- **只跳过，不兜底**：不强杀进程、不停第三方服务、不接管所有权、不修改 ACL（只有隔离根目录自身设置保护性 DACL）、不清除只读属性。遇到这些情况就跳过该项并在结果里写明原因。
- **权限最小化**：主程序清单保持 asInvoker，需要管理员的操作（ProgramData 残留、Windows\Temp、DISM、回收站之外的系统维护）交给同一个 exe 的提权 helper，helper 只接受内置操作 ID，所有路径由它自己用 Known Folder 解析，不接受命令行传入的路径。helper 还原或彻底删除批次前会核对清单：只接受两条需要管理员的 ProgramData 规则，条目锚点必须落在重新解析出的基目录内，否则整批拒绝。helper 启动的外部进程（DISM、PowerShell）使用干净环境，只带系统目录里的固定变量。

### 已知限制

- 安装包按当前用户安装，提权时运行的 `cclear.exe` 位于用户可写目录；隔离区批次目录同样对当前用户可写。两者都需要本机先有以你的身份运行的恶意程序才可能被利用，个人自用接受这一风险。
- 隔离和迁移复制文件时不保留文件自身的显式 ACL，还原后继承所在目录的权限。
- 在「清理」页点击“问 AI”时，会把当前规则的说明、脱敏后的路径片段与你的补充问题发往你配置的 AI 服务商；不配置或不触发“问 AI”时，软件不会产生任何网络请求。

## 数据位置

CClear 只在下面这些位置留下数据：

| 位置 | 内容 |
|---|---|
| `%LOCALAPPDATA%\CClear\journal\YYYY-MM-DD.jsonl` | 主程序的追加式操作日志，按天分文件，历史页的详情也来自这里 |
| `%LOCALAPPDATA%\CClear\settings.json` | 用户设置：隔离区根目录、AI 服务地址与模型名，以及以 Windows DPAPI 加密保存的 API Key |
| `%LOCALAPPDATA%\CClear\migrations.json` | 工具缓存迁移和目录迁移的状态机。写入时先写同目录的临时文件、刷盘，再原子替换；上一版留成 `migrations.json.bak`，主文件读不出来时界面会提示已改用备份 |
| `%LOCALAPPDATA%\CClear\elevated\` | 提权 helper 的请求、进度和结果文件（每次操作一个 UUID 文件） |
| `%LOCALAPPDATA%\CClear\webview\` | WebView2 的用户数据目录 |
| `<盘>:\CClearQuarantine\<批次 ID>\` | 隔离批次：`manifest.json` 记录每个条目的来源、哈希和状态，`data\` 下按锚点存放副本 |
| `<盘>:\CClearData\<工具名>\` | 工具缓存迁移后的新位置（uv、pip、npm、NuGet、Gradle） |
| `<盘>:\CClearMig\<8 位十六进制 id>\` | junction 目录迁移的目标；源位置留下同名 junction，源目录改名为 `<目录名>.cclear-bak-<id>` |
| `%ProgramData%\CClear\journal\YYYY-MM-DD.jsonl` | 提权 helper 自己的日志，与主程序日志分开写 |

`%LOCALAPPDATA%\CClear` 本身在禁区里，任何规则都不会碰它。

## 还原、迁回与撤销

- **还原一个隔离批次**：打开“隔离区”页，在批次列表里找到它，点“还原”。条目会复制回原位置并校验哈希，然后才删除隔离副本；原位置已有同名文件时视为冲突，跳过该条目并在结果里列出。需要管理员权限的批次会自动提权执行。确认副本不再需要时用“彻底删除”。
- **处理异常批次**：状态显示为需要处理的批次，可以选“继续”（逐项复核后接着删源）或“放弃”（删掉副本，保留源）。
- **把迁移的目录迁回**：打开“迁移”页的“目录迁移”区，对已经建立 junction 的条目点“迁回”。迁回以目标盘里最新的数据为准，失败时不会破坏现有内容。迁回完成后按提示“确认删除备份”，再单独决定是否删除目标盘上的旧副本。
- **撤销工具缓存迁移**：在“工具缓存目录”里对某个工具点撤销，按记录里的旧值恢复配置（旧值为空表示原来没有这个变量，撤销时会删掉它）；旧目录如果已经被清理，工具会在原位置重新生成缓存。上一次迁移在验证前被中断时，启动会自动恢复旧配置并写进说明；恢复失败的工具显示为“需要处理”，仍然可以点撤销重试。
- **看执行痕迹**：所有执行都写日志，历史页可以查看最近 30 天每条规则的删除数、跳过数、跳过原因，以及执行前后的剩余空间。

手工验收的完整步骤见 [docs/manual-test.md](docs/manual-test.md)。

## 构建与运行

环境要求：Windows 11、Rust（edition 2024，含 VS2022 C++ 生成工具）、Node.js 24、WebView2 运行时。

C 盘空间紧张时先把 cargo 目标目录放到其他盘，再开始构建：

```powershell
$env:CARGO_TARGET_DIR='G:\cclear-target'
npm ci --no-audit --no-fund
```

开发调试：

```powershell
npm run tauri dev
```

发布构建（生成 NSIS 安装包，按当前用户安装，不需要管理员）：

```powershell
npm run tauri build
```

只生成可执行文件、不打包安装程序：

```powershell
npm run tauri build -- --no-bundle
```

产物在 `$env:CARGO_TARGET_DIR\release\cclear.exe`。

其他常用检查：

```powershell
$env:CARGO_TARGET_DIR='G:\cclear-target'; cargo test -p cclear-core
$env:CARGO_TARGET_DIR='G:\cclear-target'; cargo clippy --workspace --all-targets -- -D warnings
pwsh -NoProfile -File scripts/check-forbidden-apis.ps1
```

前端只做了类型检查和打包（`npm run build`），不引入 UI 组件库、路由库和状态管理库。
